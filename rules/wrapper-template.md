# /{{name}}：{{title}}

学生敲了 /{{name}}（Codex 里是 $duck:{{name}}），后面接的文件、段落或一句话就是这次的输入。什么都没接，就问一句要处理什么。

插件根目录：开场注入的第一行写着。没有这一行时，就是这份文件往上两级的目录，因为这份文件在「插件根目录/skills/{{name}}/SKILL.md」。下文的路径都相对插件根目录；「项目」指学生当前的工作目录。

{{basics}}

## 1. 先查两件事
- 读项目的 .duck/config.md，没有就跳过这一条。「关掉的命令」（英文的 config 里叫 Disabled commands）下面写了 {{short}}，就回一句「/{{name}} 已关闭，敲 /duck-skill enable {{short}} 可以打开。」然后停下。
- 项目里有 .duck/skills/{{name}}/SKILL.md，而你现在读的不是它：改读那一份，从头照做，这一份不再往下读。

## 2. 读组里的卡、笔记本和「我自己定」
- 项目有 .duck/cards/INDEX.md 的话，读它，挑出和这次任务相关的卡，读卡的正文，当作这一次的规矩：{{card_use}}。没有就跳过。
- 项目有 .duck/notebook.md 的话，也读一遍，挑出和这次任务相关的旧条目，至多三条：同一阶段的，或者讲的是同一件事的。干活时照着做；收尾讲解里用上了哪条，就点出来，写成「笔记本 MM-DD 那条：……」。一条都不相关，就不提。
- .duck/config.md 里有「我自己定」（I decide）一节的话，看这次要做的事里有没有那一类决定。有，动手前先问学生这一件，问完就停。Ducktor 没开启时也问：学生敲了命令，又说过这一类要自己定。

## 3. 照原技能做
{{skill_block}}
- 先把原技能的 SKILL.md 读完再动手。学生只要其中一部分（比如只写一节、只查一项）也一样：SKILL.md 里的硬规则照样管这一部分；references/ 下的文件按 SKILL.md 的指引再读，不跳过 SKILL.md 直接去读 references/。
- 原技能写的相对路径（references/…、scripts/…、templates/… 这类）都相对它自己的文件夹 library/<技能名>/，不是相对这份文件。
- 原技能点到别的技能名时，换成对应的命令：deep-research → /duck-survey；idea-evaluator → /duck-idea；tech-paper-template、benchmark-paper-template → /duck-outline；intro-drafter → /duck-intro；paper-writer → /duck-write；paper-polish → /duck-polish；figure-designer → /duck-figure；pre-submission-reviewer → /duck-review；vibe-research-workflow → /duck-vibe。
- 原技能要求的步骤、检查和输出格式全部照做，不因为外面包了一层就省略。
- 原技能多是照计算机方向（数据库、AI）的论文写的。学生不是这个方向时（比如历史、社会学、管理学的开题报告或论文），原技能的结构和要求里只对计算机论文成立的部分（基线、消融、种子、系统实现这类），换成学生那一行的对应做法；没有对应的，说明不适用，不硬套。学生那一行的惯例（学校的开题格式、引文格式、研究方法的写法）优先。{{extra}}

## 5. 挑卡
读插件根目录下的 cards/INDEX.md。这是插件自带的卡，和第 2 步项目里的 .duck/cards/ 是两回事：项目里没有组卡，这一步照样做。挑至多三张认同程度是「共识」的卡：和这次的产物相关，不在 .duck/config.md 的「静音的卡」（Muted cards）里，也没钉在第 4 步。挑中的写进报告的「卡片提醒」一节：每条先写卡名，括号里标卡号，再写一句它对这次产物的提醒，只提醒，不定轻重，不混进原技能的结果。对话里不列卡；最要紧的那一张讲的道理，可以化进收尾的讲解。一张都不相关，报告里就不写这一节。

## 6. 收尾
先看开关：.duck/config.md 里「开关：」那一行（英文写的 config 里是「Switch:」）。写的既不是 on 也不是 quiet（中文的开、打开、开启、启用算 on，静音、安静算 quiet），或者没有这个文件、没有这一行，都是 Ducktor 没在这个项目开启（off 也是），这条命令照 on 收尾：学生敲了命令，就是这一次要它。

on：
1. 交出原技能的结果。{{result_note}}
2. 结果后面空一行，按「怎么讲」讲这次最要紧的一个判断，写成一个引用块（每行以「> 」开头），和原技能的结果分开，一般两到四行。讲的是这次的取舍和道理：这样做让结论更可信、读者更好懂，或者实验更省事在哪里。道理要自己讲得通，不拿「原技能要求」「Step N 规定」当理由；你没照原技能做的地方，可以直说并讲原因。这次只是按部就班、没有值得讲的取舍时，一句话说明就够。原技能的结果里要引原句、给改后的句子，用代码块或引号（原技能的输出格式里规定了引用块的照旧）。
3. 这一步有取舍时，在引用块最后加决策行：「▸ 决策：选了什么，放弃了什么（谁定的）」；第 2 步因为按类静音没讲时，决策行单独写成一行引用块。追加到 .duck/decisions.md 时写成一行：「- YYYY-MM-DD ▸ 决策：……（谁定的）」，不加标题，前后不空行。
4. 把完整报告写进 .duck/reports/今天的日期-{{short}}.md，日期写成 YYYY-MM-DD，重名就在后面加 -2、-3。内容是原技能的完整结果（对话里给过的问题清单、表格和逐条修法都要在，不只存要点），加上这几节：做了什么；这次的取舍和道理（写明依据：卡名加卡号、名家和文章、手册章节，或「自己的判断」）；卡片提醒（第 5 步挑中的，没有就不写）；带走的原则和下次自己先做什么（讲解里说了才写）。学生用英文时，标题写成 What I did、The trade-off and why、Card reminders、To take away。
5. 讲解里说出了一条值得带走的原则时，把那一句追加到 .duck/notebook.md（只抄原则，不带「你能带走的一条」这类开头），一行一条：「- MM-DD {{stage}}｜原则（出处）｜这次：一句话说这次碰到的具体事」，前后不空行。出处这样写：原则就是 MENTORS.md 那一格或卡片的意思，写名家和文章，或卡名加卡号；是你自己概括的，写「自己的判断，参照某某」；都没参照，写「自己的判断」。原技能的规则不当出处。没说出原则，或者笔记本里已经有同一条原则的，不记。
6. 这一类在 .duck/config.md 的「按类静音」（Muted topics）里时，第 2 步不在对话里讲，第 3 到 5 步照做。

quiet：对话里只交原技能的结果；决策行、报告和笔记照样写进文件（笔记本记你本来会讲出的那条原则）。

.duck/ 和里面的文件不存在时，用到才建。
