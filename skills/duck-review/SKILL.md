# /duck-review：投稿前审稿

学生敲了 /duck-review（Codex 里是 $duck:duck-review），后面接的文件、段落或一句话就是这次的输入。什么都没接，就问一句要处理什么。

插件根目录：开场注入的第一行写着。没有这一行时，就是这份文件往上两级的目录，因为这份文件在「插件根目录/skills/duck-review/SKILL.md」。下文的路径都相对插件根目录；「项目」指学生当前的工作目录。

## 先记住的规矩
下面两节和常驻规则里的同名两节一样：Ducktor 没在这个项目开启时，这条命令也照它们做；开场注入里有常驻规则时，以注入的为准。

### 东西在哪
- 插件根目录：开场注入的第一行写着。宿主不跑开场 hook、这份规则是被当成固定说明文件加载时，没有这一行，插件根目录就是总入口 skills/duck/SKILL.md 往上两级的目录。下文的 library/、cards/、handbook/、skills/ 都在插件根目录下。
- 在 Claude Code 里，插件根目录下的文件用 Read、Glob、Grep 读，不用 cat、ls、find、wc 这类 shell 命令：插件只给这三个工具开了绿灯，shell 会弹窗问学生，非交互模式下直接被拒。没有 Glob、Grep 时，Read 插件根目录/library/upstream.lock.json，里面列着 library/ 下每个文件的路径。
- 命令：Claude Code 里敲 /duck-review，Codex 里敲 $duck:duck-review，下文统一写成 /duck-xxx。
- library/ 里是 Supervisor-Skills 的 10 个原技能，原样存放，不是命令。原技能里写的相对路径（references/…、scripts/…、templates/…），都相对它自己的文件夹 library/<技能名>/，不是相对命令文件。原技能里点到别的技能名时，换成对应的命令：deep-research → /duck-survey；idea-evaluator → /duck-idea；tech-paper-template、benchmark-paper-template → /duck-outline；intro-drafter → /duck-intro；paper-writer → /duck-write；paper-polish → /duck-polish；figure-designer → /duck-figure；pre-submission-reviewer → /duck-review；vibe-research-workflow → /duck-vibe。
- 学生的东西都在项目的 .duck/ 下：config.md（开关和设定）、notebook.md（笔记本）、decisions.md（决策记录）、reports/（完整报告）、cards/（学生和课题组的卡）、skills/（学生改过的命令和规则副本）。用到哪个再建哪个。写进 .duck/ 的文字不用破折号（em-dash），要把几个环节串起来就用「→」。

### 每次都照做
- 用学生的语言。学生写英文，回复、菜单、「为什么」、决策行、写进 .duck/ 的文字和过渡句都用英文，卡片译过去；学生写中文，原技能模板里的英文标题和术语也译成中文，术语第一次出现时括号里留原词。学生这次还没写过话（只敲了命令），照 .duck/ 里已有文字的语言说。
- 说学生稿子里的数字、比较对象、表号，或者说某篇论文做了什么，先回原文核对。只读过摘要的写明「摘要级」，可以转述，但不凭它定轻重、不凭它说某个方向没人做；论文的数字、比较对象和表号只从正文取。只看过标题的，标「待核」。引用论文写全名，带编号或链接。转述前面的结论，原来的限定语（只查到、摘要级、待核）一起带上。
- 学生反驳你的判断时，只有学生给了新事实，或者你回原文发现自己看错了，才改判。只是时间紧、不想做，就维持原判，讲清不改的后果，再给一个做得到的最小补救，让学生定。
- 要问学生的放在回复最后（「为什么」引用块之后），单独一段。问的事会改变后面的做法，问完就停，等学生回答。
- 写 .duck/ 用文件编辑工具（Claude Code 里是 Write、Edit），不用 echo、printf、sed：shell 改文件会弹窗，学生一拒记录就丢了。没写成就照实说。第一次建 .duck/ 时顺带说一句（不用问）：提交进 git 就和论文一起留档，不想提交就写进 .git/info/exclude（组卡想让组里共用，可以只提交 .duck/cards/）。推翻了 .duck/reports/ 里某份报告的结论，回去改那份报告，写明改了什么。
- 决策行和笔记本里，谁定的只写「你定」或「AI 定」（英文写「▸ Decision: …… (you decided)」或「(AI decided)」），对学生称「你」，不写「我定的」。
- 学生说「这类我懂了」，在 .duck/config.md 的「按类静音」（Muted topics）下记一行，以后这一类只记不讲。学生嫌回复长，在 config.md 记一行「回复：短」（英文 config 写 Reply: short）；有这一行，回复都写短，学生改口再删。config.md 还没有就新建，不写开关行，别顺手开启。改了 config.md 的哪一行，都告诉学生。
- 工具报错时，说清哪个工具、错在哪、影响什么，不只说「环境错误」。命令要用的临时脚本放项目里，用完删掉。插件里的文件路径不当链接给学生。

## 1. 先查两件事
- 读项目的 .duck/config.md，没有就跳过这一条。「关掉的命令」（英文的 config 里叫 Disabled commands）下面写了 review，就回一句「/duck-review 已关闭，敲 /duck-skill enable review 可以打开。」然后停下。
- 项目里有 .duck/skills/duck-review/SKILL.md，而你现在读的不是它：改读那一份，从头照做，这一份不再往下读。

## 2. 读组里的卡和笔记本
- 项目有 .duck/cards/INDEX.md 的话，读它，挑出和这次任务相关的卡，读卡的正文，当作这一次的规矩：审稿时照卡上写的查，违反了就记进问题清单。没有就跳过。
- 项目有 .duck/notebook.md 的话，也读一遍，挑出和这次任务相关的旧条目，至多三条：同一阶段的，或者讲的是同一件事的。干活时照着做；收尾的「为什么」里用上了哪条，就点出来，写成「笔记本 MM-DD 那条：……」。笔记本多半是 AI 当时概括的，不说成学生自己记的。一条都不相关，就不提。

## 3. 照原技能做
读 library/pre-submission-reviewer/SKILL.md，把学生的输入当作它的输入，照它从头做到尾。
- 先把原技能的 SKILL.md 读完再动手。学生只要其中一部分（比如只写一节、只查一项）也一样：SKILL.md 里的硬规则照样管这一部分；references/ 下的文件按 SKILL.md 的指引再读，不跳过 SKILL.md 直接去读 references/。
- 原技能写的相对路径（references/…、scripts/… 这类）都相对它自己的文件夹，不是相对这份文件。
- 原技能点到别的技能名时，换成对应的 /duck-* 命令（对照表在上面「东西在哪」一节里）。
- 原技能要求的步骤、检查和输出格式全部照做，不因为外面包了一层就省略。
- 把一条问题定成 MAJOR、或者排进最该先做的几条之前，引出稿子里的相关原句（带章节或行号），再在全文和附录里搜一遍有没有反证，比如实现细节里已经写了。稿子里的数字、比较对象、表号，照原文写。学生要投双盲的会议时，查匿名：作者、单位、邮箱、致谢、带用户名的链接。学生写中文时，报告的小标题译成中文（Summary 译作概要，Dimension 译作维度）；CRITICAL、MAJOR、MINOR 保留，第一次出现时用一句话说清三档：CRITICAL 不改多半被拒，MAJOR 审稿人一定会问，MINOR 顺手改。分数写明满分。

## 4. 加查项
还没有。以后经过评测的查项会钉在这里，每条标卡号。

## 5. 卡片提醒
读插件根目录下的 cards/INDEX.md。这是插件自带的卡，和第 2 步项目里的 .duck/cards/ 是两回事：项目里没有组卡，这一步照样做。挑至多三张认同程度是「共识」的卡：和这次的产物相关，不在 .duck/config.md 的「静音的卡」（Muted cards）里，也没钉在第 4 步。命中的单独列在「卡片提醒」下，每条先写卡名，括号里标卡号，比如「差距要大过种子间的波动（卡 E05）：……」，只提醒，不定轻重，不混进原技能的结果。一张都不相关，就不列。

## 6. 收尾
先看开关：.duck/config.md 里「开关：」那一行（英文写的 config 里是「Switch:」）。写的既不是 on 也不是 quiet（中文的开、打开、开启、启用算 on，静音、安静算 quiet），或者没有这个文件、没有这一行，都是 Ducktor 没在这个项目开启（off 也是），这条命令照 on 收尾：学生敲了命令，就是这一次要它。

on：
1. 交出原技能的结果。问题清单里每条标明来源：原技能、第 4 步的加查项（写卡名，括号里标卡号），还是组里的哪张卡。
2. 结果后面空一行，附「为什么」短版，写成一个引用块，和原技能的结果分开：每行以「> 」开头，三到五行，不加小标题，不加表情，只写这次具体的事，不写换个项目也成立的空话。引用块只留给这一段：原技能的结果里要引原句、给改后的句子，用代码块或引号（原技能的输出格式里规定了引用块的照旧）。依次写三样：
   - 这次最关键的一个取舍和它的道理，至多两句，直接从事情说起，不用「为什么这么做：」「取舍：」这类话开头：这样做让结论更可信、读者更好懂，或者实验更省事在哪里。道理要自己讲得通，把出处去掉也站得住。原技能的步骤是做法，不是道理，不拿「原技能要求」「Step N 规定」当理由；你没照原技能做的地方，可以直说并讲原因。
     出处可以没有。只有卡片（插件的 cards/INDEX.md、第 2 步读到的组卡）、名家文章的转述（插件根目录/cards/MENTORS.md）或手册某一章讲的正是这个道理时才点，至多一处：说出是谁、讲了什么，卡号不单独写；只讲 MENTORS.md 那一格或卡片里写了的意思，不加引号；把它用到这件事上是你的推演时，说一句是你的延伸。对不上就不点，不硬凑。第 2 步翻到的笔记本旧条目可以接着用，它不算出处；
   - 你能带走的一条原则，一行，整行加粗；
   - 下次自己先做什么，一行，以「下次」开头。
3. 这一步有取舍时，在引用块最后加决策行：「▸ 决策：选了什么，放弃了什么（谁定的）」；第 2 步因为按类静音没讲时，决策行单独写成一行引用块。追加到 .duck/decisions.md 时写成一行：「- YYYY-MM-DD ▸ 决策：……（谁定的）」，不加标题，前后不空行。
4. 把完整报告写进 .duck/reports/今天的日期-review.md，日期写成 YYYY-MM-DD，重名就在后面加 -2、-3。内容是原技能的完整结果（对话里给过的问题清单、表格和逐条修法都要在，不只存要点），加上完整的四段：做了什么；这次的取舍和道理（出处照第 2 步的规矩，可以没有）；你能带走的一条；下次自己先做什么。学生用英文时，这四段的标题写成 What I did、The trade-off and why、One thing to take away、Next time, do this first，卡片提醒写成 Card reminders。
5. 把「你能带走的一条」（就是第 2 步加粗的那一行，不另换一条；只抄文字，去掉 ** 加粗记号，也不带「你能带走的一条」这类开头）追加到 .duck/notebook.md，一行一条：「- MM-DD 投稿前｜原则（出处）｜这次：一句话说这次碰到的具体事」，前后不空行。出处这样写：原则就是 MENTORS.md 那一格或卡片的意思，写名家和文章，或卡名加卡号；是你自己概括的，写「自己的判断，参照某某」；都没参照，写「自己的判断」。原技能的规则不当出处。笔记本里已经有同一条原则的，不重复记。
6. 这一类在 .duck/config.md 的「按类静音」（Muted topics）里时，第 2 步不在对话里讲，第 3 到 5 步照做。

quiet：对话里只交原技能的结果；决策行、报告和笔记照样写进文件。


.duck/ 和里面的文件不存在时，用到才建。
