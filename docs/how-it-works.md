# Ducktor 是怎么运行的

这一篇讲现在的实现，给想改插件、或者想把它接到别的 agent 上的人看。设计过程和讨论在 `docs/design/`，两边说法不一致时以这一篇为准。

## 仓库里有什么

```
.claude-plugin/  .codex-plugin/  .cursor-plugin/  .agents/plugins/  gemini-extension.json   各宿主的清单
hooks/  bin/duck.js     开场注入、读插件文件和追加记录的放行（Node，不装依赖）
rules/                  常驻规则、命令模板、命令表
skills/                 14 条命令
library/                Supervisor-Skills 的 10 个原技能（上游提交 aff5de9），原样存放
handbook/               科研导师手册的文字版（zh、en）
cards/                  经验卡片 23 张，每张写明道理和出处；MENTORS.md 是名家文章索引
scripts/  tests/        生成、同步上游、测试
docs/                   说明文档、设计记录、调研
AGENTS.md               给不跑 hook 的 agent 用的常驻规则（生成的）
```

## 三层东西

| 层 | 在哪 | 是什么 | 谁写的 |
|---|---|---|---|
| 常驻规则 | `rules/core.md` | 平时怎么陪学生：先问、讲为什么、记决策、结果进论文前对标准、只提议不自动跑、放手 | 我们 |
| 命令 | `skills/duck*/SKILL.md` | 学生敲的 `/duck`、`/duck-review` 等 14 条 | 我们 |
| 原技能 | `library/` | Supervisor-Skills 的 10 个技能，逐字节照搬 | 上游 |

命令只是一层包装：先查设定、读组里的卡和学生的笔记本，再让 AI 去读 `library/` 里的原技能照做，最后按开关写「为什么」报告。原技能一字不改，上游更新时整体同步。

## 开场：hook 注入三样东西

开会话时，宿主跑 `hooks/claude-codex-hooks.json` 里的 SessionStart hook，它调 `bin/duck.js session-start`，往上下文里放：

1. 插件根目录的绝对路径。每台机器、每次升级路径都不一样，所以每次都告诉 AI。
2. 按开关放一段规则。Ducktor 要在项目里开启才主动：开关是 on 或 quiet，放常驻规则（项目里有学生改过的 `.duck/skills/core.md` 就用它，否则用插件的 `rules/core.md`）；没开启或者开关是 off（两者一样），放 `rules/idle.md` 那一小段，说平时照常干活，只有学生敲命令时才照命令做。
3. 项目 `.duck/config.md` 的内容（最多 1,000 字，0.2.1 以前是 1,200；更长的部分 AI 要用时自己读文件），以及从中读出的开关。有「回复：短」这一行时，再加一句话提醒每条回复都写短。没有这个文件就不放。

开启了的项目注入约 5,800 字符：0.2.3 在同一个 46 字符长的插件路径下实测 5,771；config.md 写满 1,000 字时 6,789；再加「回复：短」、英文提醒和一个读不了的字节，最多 6,979。单元测试要求最多的情况小于 7,000，还能再加 20 字，往 rules/core.md 加字之前先删字；插件路径比 46 字符长 21 字符以上时，这个测试会先失败，实际注入不受影响；Claude Code 自己的上限是 10,000。没开启的项目只注入约 700 到 800 字符（0.2.3 在一个 46 字符长的插件路径下实测 771，路径越长越多）：插件根目录一行，加上 `rules/idle.md` 那一小段。装了插件的每个项目、每次会话都要付这一份，所以只放这么多。命令要用的三节常驻规则（「东西在哪」：插件文件在哪、在 Claude Code 里用 Read 读、`.duck/` 里不用破折号；「每次都照做」：用学生的语言、核对原文、被反驳时怎么办、问题写进回复、`.duck/` 用编辑工具写、记设定；「怎么讲」：讲解怎么判断、怎么写、依据怎么用、非计算机学生怎么换说法），由 `scripts/build.js` 从 `rules/core.md` 原样抄进每条命令开头的「先记住的规矩」一节，敲命令时才进上下文。只有命令用得到的几条（第一次建 `.duck/` 时说一句它是干什么的；没开启时记「我自己定」要照实说只有敲命令才先问）写在 `rules/command-basics.md`，作为第四节抄进命令，不进开场注入。原技能名和命令的对照只在包装命令的第 3 步里（只有照原技能做时才用得到）。总入口 `/duck` 不抄：它只列菜单、切开关、挑命令，挑中的命令自己带着这一节；在开启了 Ducktor 的项目里，总入口里再放这一节时（放在开头、放在末尾都试过），`/duck` 后面接一句话多半不挑命令、自己就答了（10-28 的对照见 `docs/testing.md`）。开着 Ducktor 时注入里已经有这三节，命令里那份以注入的为准。Claude Code 对 hook 注入的上限是 10,000 字符，超过的部分会被写进会话目录下的文件，上下文里只留前 2,000 字符的预览和文件路径。会话恢复、清空、压缩、分叉时 hook 会重跑。

`bin/duck.js` 只读文件、拼文字，规则的原文都在 `rules/` 下，不写进代码。这样代码可以用 MIT，文字用 CC BY-NC-SA，两者不混（见 `LICENSES/README.md`）。

## 一条命令怎么走

以 `/duck-review paper/main.tex` 为例，`skills/duck-review/SKILL.md` 让 AI：

1. **先查两件事**：`.duck/config.md` 的「关掉的命令」里有没有 review；项目里有没有学生改过的副本 `.duck/skills/duck-review/SKILL.md`，有就改读副本。
2. **读组里的卡、笔记本和「我自己定」**：项目的 `.duck/cards/INDEX.md`，挑出相关的，当作这一次的规矩；项目的 `.duck/notebook.md`，挑至多三条和这次任务相关的旧条目照着做，收尾讲解里用上了就点出来（「笔记本 MM-DD 那条：……」；笔记本多半是 AI 当时概括的，不说成学生自己记的）；`.duck/config.md` 的「我自己定」里记了这次要碰到的那一类决定，动手前先问学生。
3. **照原技能做**：读 `library/pre-submission-reviewer/SKILL.md`，从头做到尾。原技能里的相对路径（`references/…`）相对它自己的文件夹；原技能点到别的技能名，换成对应的命令。原技能多是照计算机论文写的，学生是别的方向时，只对计算机论文成立的要求（基线、消融、种子这类）换成学生那一行的做法，或者说明不适用。
4. **加查项**：经过评测的额外检查钉在这里，现在还是空的。
5. **挑卡**：从插件的 `cards/INDEX.md` 挑至多三张共识卡对照，写进报告的「卡片提醒」一节，对话里不列卡号；最要紧的那一张讲的道理，可以化进收尾的讲解。插件自带的卡现在有 23 张（写作、选题、实验、作图、报告、找反馈、审稿），每张写明道理、怎么用、出处和认同程度（共识、有出处、有分歧），出处都是我们自己的话转述。
6. **收尾**：按开关。on 时对话里在结果后面附一个引用块，照常驻规则「怎么讲」讲这次最要紧的一个判断（一般两到四行；按部就班、没有取舍时一句话），没有固定的段落：不单独加粗一行原则，不固定写「下次」，对话里不报人名、文章名和卡号。有取舍再加决策行；决策行追加到 `.duck/decisions.md`，完整报告写进 `.duck/reports/`（原技能的完整结果，加上做了什么、取舍和道理连同依据、卡片提醒、带走的原则和下次先做什么），讲解里说出了原则，就把那一句追加到 `.duck/notebook.md`，写成「- MM-DD 阶段｜原则（出处）｜这次：……」（已有同一条原则的不重复记）。quiet 时只写文件。没开启和 off 时照 on 收尾：学生敲了命令，就是这一次要它。0.2.0 以前收尾是固定的三样（取舍、加粗原则、「下次」）加卡片提醒；11-03 的发布前检查里 61 次收尾 61 次都是这个结构，读起来像填表，0.2.1 改成上面这样。

   为什么用引用块：终端里能和干活的输出分开的格式，两个宿主都认的只有它。10-19 在 tmux 里实测：Claude Code 在每行前面画一道暗色竖线，正文颜色不变；Codex 显示「> 」，整行绿色；加粗两边都认。代码块两边都没有边框和底色；用制表符画的全框遇到中文宽度会错位；插件也没法指定颜色。别的宿主不认 markdown 时，引用块退化成以「> 」开头的普通行，照样能读。

九条包装命令结构相同，由 `scripts/build.js` 从 `rules/wrapper-template.md` 和 `rules/commands.json` 生成。要改步骤就改模板，再跑 `npm run build`。`/duck`、`/duck-why`、`/duck-learn`、`/duck-notes`、`/duck-skill` 是手写的。

## 三条路进到同一份命令文件

- 学生直接敲 `/duck-review`：宿主把文件正文交给 AI。
- 学生敲 `/duck 帮我审一下`：总入口挑一条命令，说一句按哪条处理，再用读文件的办法读 `skills/duck-review/SKILL.md` 照做。
- 学生没敲命令，AI 按常驻规则提议「这件事 /duck-polish 能做，要按它来吗？」，学生点头后，同样读那份文件照做。

后两条路是当普通文件读的，宿主不会替换 `${CLAUDE_PLUGIN_ROOT}` 这类变量，frontmatter 里的设置也不生效。所以命令文件里不用变量，frontmatter 只放名字、描述和「只能手动调用」（`disable-model-invocation: true`；Codex 那边是每条命令文件夹里的 `agents/openai.yaml`）。

## 读插件自己的文件

Claude Code 默认不让读工作目录以外的文件：交互时每次弹窗问，`-p` 模式下直接拒绝。插件也没办法通过清单给自己加可读目录。所以插件带了第二个 hook：PreToolUse，匹配 Read、Glob、Grep、Write、Edit、MultiEdit、Bash，调 `bin/duck.js allow`。读：目标路径（解开符号链接以后）在插件根目录下才回答 allow。写：只放行项目 `.duck/` 下 Ducktor 自己记的几样，`notebook.md`、`decisions.md` 和 `reports/` 下的 `.md`。项目按 `CLAUDE_PROJECT_DIR` 认（没有才用 hook 输入里的 cwd），AI `cd paper` 以后照样放行；路径都解开符号链接再比。笔记本和决策记录是学生拿去组会用的日志，只放行追加：新建或空文件；Write 或 Edit 照宿主的做法套到原文件上以后，原文件一字节不差地留在开头。用 Edit 改旧行、删行、往旧行中间插字、replace_all 照常问。用 Write 整份写、又没把原文件留在开头的，回答 deny，并告诉模型先读、再用 Edit 在末尾追加：2026-11-04 的试用里，第二天的新会话用 `ls -R .` 看项目（不列隐藏目录），没读笔记本就用 Write 写了一行，前一天的两条没了；那次会话开着自动接受编辑，Claude Code 2.1.318 也没要求先读。同样的探针在改后的插件上，自动接受编辑和 bypassPermissions 两种模式下都被拦下，两条都在。删改某一条走 Edit，不受影响。`.duck/`、`reports/` 或文件本身是符号链接或硬链接的不放行；`config.md`、`skills/`、`cards/` 下一次会话会当设定和规则读进来，照常问学生。2026-10-27 的学生旅程测试里，AI 用 shell 往笔记本追加被权限拦下，记录就丢了，所以加了写这一半。常驻规则也让 AI 用编辑工具写 `.duck/`，可 rc10 的 Claude Code 6 套运行里仍有 2 套用 echo、printf 加 `>>` 写决策记录和笔记本（测试开着自动接受编辑，没弹框）。所以 0.2.1 起 hook 也看 Bash：命令用 `>`、`>>`、`tee`、`sed -i` 或 `perl -i` 写 `.duck/notebook.md`、`.duck/decisions.md` 时回答 deny，告诉模型先读、再用 Edit 在末尾追加。读日志的命令（cat、grep、tail、sed -n）、写别的文件的命令、cp 和 mv 都不管。11-04 在默认权限模式下的探针（Claude Code 2.1.318，Sonnet 5.5，跑一次）：模型先用 echo 追加，被拒，接着读文件、用 Edit 追加，没有弹框，旧的两条都在。别的路径一律不回答，照宿主原来的规矩走。读文件的 shell 命令（cat、ls、find）不在放行范围里，照宿主原来的规矩走（交互时弹窗问，`-p` 模式下拒绝），所以常驻规则让 AI 用 Read 读插件文件。Glob 的 pattern 和 Grep 的 glob 过滤也会指到文件，所以带 `..`、`~` 的不放行，绝对路径的要落在插件根目录下。Linux 上的 Claude Code 默认没有 Glob、Grep 这两个工具（找文件走 Bash 的 find），常驻规则让 AI 改读 `library/upstream.lock.json`，那里列着 `library/` 下每个文件的路径。

11-04 用 Claude Code 2.1.318 看到，它给模型的工具里已经没有 Glob、Grep（会话开头的 init 事件里列着工具）。所以常驻规则让 AI 只用 Read 读插件的文件，列 library/ 的文件改读 library/upstream.lock.json；hook 对 Glob、Grep 的放行留给还有这两个工具的版本。

这条 hook 只跳过「要不要允许」的询问；据 Claude Code 的权限文档，用户自己设的 deny、ask 规则照样生效。用户开了 `blockReadsOutsideWorkingDirectories` 时它还管不管用，文档没写，我们也没测。

Codex 的沙箱默认能读整个文件系统，不需要这条；它的工具名也不叫 Read，这条 hook 在 Codex 里匹配不到任何东西。

## 学生项目里的 `.duck/`

```
.duck/
  config.md      开关（on / quiet / off）、我自己定、按类静音、静音的卡、关掉的命令；学生说了才加的「回复：短」「讲法：直接讲」
  notebook.md    笔记本：- MM-DD 阶段｜原则（出处）｜这次：……
  decisions.md   决策行：- 日期 ▸ 决策：选了什么，放弃了什么（谁定的）
  reports/       每条命令的完整报告（结果、取舍和依据、卡片提醒），日期-命令.md
  cards/         学生和课题组的卡，带 INDEX.md，卡号 G01 起
  skills/        学生改过的命令和规则副本
```

用到哪个建哪个。插件目录本身只读，学生的改动都在项目里，可以进 git，随时回退。

## 开关

| 开关 | 常驻规则 | 命令跑完 | `/duck-why`、`/duck-learn` |
|---|---|---|---|
| 没开启（默认：没有 config.md，或者没有开关行） | 不注入，换成 idle.md 一小段 | 和 on 一样：学生敲了命令，就是这一次要它 | 照常讲，写文件 |
| on | 注入 | 对话里放一段讲解，文件照写 | 照常讲，写文件 |
| quiet | 注入 | 对话里只交结果，文件照写 | 照常讲，写文件 |
| off | 和没开启一样：换成 idle.md 一小段 | 和没开启一样 | 照常讲，写文件 |

on 和 quiet 下，平时干活（不敲命令）开始一段实质性的工作前，先读笔记本，挑出同一阶段或同一件事的旧条目照着做（平时第 6 条）；做完一步、有一条值得带走的原则时，也往笔记本记一行：先读笔记本，意思相同的不记，一轮至多一条，小改动不记（`rules/core.md` 笔记本那一段）。quiet 时对话里不说，笔记本照记，这是给不想在对话里看 Ducktor 讲话的人用的。「我自己定」里记的那一类决定，on 和 quiet 平时都先问；没开启和 off 时平时不问，敲包装命令时才问。

开关行写错时（比如 `开关：offline`），按没开启处理，并在注入里提醒 AI 告诉学生。中文的「开、开启、关、关闭、静音」也认。

没开启的项目里，命令照样会建 `.duck/` 写报告、决策和笔记，但不会写开关行，所以下次开会话仍然是没开启。`/duck-skill disable` 新建 config.md 时也不写开关行。

会话中途敲 `/duck on`：`skills/duck/SKILL.md` 让 AI 当场去读常驻规则，从这一轮起照做；`rules/idle.md` 也写明开启以后那一段不再算数。端到端测试只验证了开启的那一轮确实读了规则：测试每一步都是一次 `claude -p --resume` 或 `codex exec resume`，两个宿主在恢复会话时都会重跑 hook，所以后面几步拿到的规则来自 hook。交互会话里中途开启以后，规则能不能一直管住后面的对话，没有单独测过；压缩上下文或下次开会话时，hook 会按新开关重新注入。

## 生成的文件和上游副本

- `npm run build`：重新生成九条包装命令和 `AGENTS.md`。
- `npm run check`：生成的文件是否最新；`library/`、`handbook/` 是否还和上游一致（`library/upstream.lock.json` 记着每个文件的 sha256 和上游提交）。
- `node scripts/upstream.js sync <上游仓库目录>`：从新版 Supervisor-Skills 同步，同时更新锁文件，并列出变了哪些文件。
