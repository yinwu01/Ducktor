# 看它干活：一轮完整的演示

README 首页只放了一段对比，这一页是完整的一轮。下面是 2026-11-04 端到端测试主流程的原话，节选，跑在 0.2.1 的候选版 rc7（提交 e4d2267）上。项目是虚构的（[`tests/fixtures/grad-project`](../tests/fixtures/grad-project)）：一个研究生在做长文本推理加速，手里有中文的实验笔记、一段代码和一份英文论文草稿，草稿里写着 delve into、game-changer 这种词。跑在 Claude Code 2.1.318 里，模型是 Sonnet。学生的话是测试脚本写好的；每一步跑的是同一个会话。

## 敲 /duck on，再审一遍稿子

这个项目先敲了 `/duck on`。审稿用的是 `/duck-review`，它照 Supervisor-Skills 的投稿前审稿技能走，结果开头是这样：

```
你：/duck-review paper/main.tex

AI：**评分 3/10(满分 10),建议投稿前大修。** 2 项 CRITICAL(不改多半被拒),9 项 MAJOR(审稿人一定会问),
  6 项 MINOR(顺手改)。我读了 `paper/main.tex` 全文,并对照了 `notes.md` 和 `code/skip_attn.py`。……
  没有联网检索权限,所以查新和引用完整性这两项没做。凡涉及相关工作的地方都标"待核"。

  **CRITICAL**
  1. **缺关键基线**
     - 摘要第 10 行写"significantly outperforms existing sparse attention methods",结论第 45 行写
       "significantly outperforms prior work"。
     - 表 1(第 34 到 36 行)只有稠密注意力和 token 剪枝,没有任何稀疏注意力方法,也没有显著性检验。
     ……
```

审稿结果后面，Ducktor 只讲这次最要紧的一个判断，写成一段引用，和审稿结果分开。最后一行是决策行，同时记进 `.duck/decisions.md`：

> 这次最要紧的一条是:摘要和结论里点名的比较对象,表里必须有对应的一行。你现在写了"优于现有稀疏注意力方法",证据撑不住这句话,审稿人第一眼就会挑它。
> ▸ 决策:审稿只出清单不改稿,措辞类修改(significantly、game-changer 等)等证据补齐后再做(AI 定)

讲的是道理，没有报卡号和人名。出处写在 `.duck/reports/` 的报告里，你问起时它直接给。

## 一小步也敲 /duck-why

接着让 AI 把摘要第一句改紧凑，然后敲 `/duck-why`。这一步本身没什么取舍，它直说了，只讲是谁挑的、代价在哪、去哪核对，再点出这次会话里更值得问的那一步：

```
你：/duck-why
```

> 这一步本身可讲的不多。你只给了"更紧凑"这个方向,删哪些词是我挑的:去掉原因从句里的 "with sequence length",保留 "quadratic" 和 "attention cost"。代价是"对什么而言的二次方"这句里不再写出,引言第 15 行还保留着完整说法。是否合适,你可以对照 `paper/main.tex` 第 8 行和第 15 行自己判断。
>
> 这次会话里更值得讲的是上一步审稿:摘要和结论点名的比较对象,表 1 里必须有对应的一行。想听可以敲 `/duck-why` 指定那一步。

## 一段做完，敲 /duck-learn

中间还切过 `/duck quiet`（对话里不讲，照样记），让 AI 把代码里的跳块阈值改成每层 90% 分位数，又建了一张课题组的卡。然后复盘这一段。对话里是几段话，没有固定的标题；报告里照旧五节：

```
你：/duck-learn
```

```
AI：这一段最要紧的是:稿子里的数字和现在的代码已经对不上了。摘要里的 31%、71.2、1.45×,都是固定阈值 1e-3
  的代码跑出来的。你把阈值改成 90% 分位数以后,每次只保留约 10% 的块,这些数字不再对应当前代码。`notes.md`
  里它们本来就只跑了一次。改完代码后要重跑主表,摘要再回头改。

  第二件事排在第一件之前就该做,到现在还没做:核对块估计器。……论文说"估计注意力质量",代码算的是块均值点积的
  绝对值。用稠密注意力统计被跳过的块真实占多少 softmax 质量,是最便宜、也最能说明方法站不站得住的实验。

  交给 AI 定的判断有这几项:
  - 评估结论和"先核对估计器、补基线"的顺序。
  - 审稿只出清单、不改稿。
  - 摘要第 10 行放软。这一条还没得到你的确认。
  ……
  阈值改成分位数是你定的。

  下一步:
  1. 先核对估计器。
  2. 用当前代码重跑主表,标明种子数(按新加的 G01)。
  3. 补稀疏注意力基线并做查新。

  完整复盘在 `.duck/reports/2026-11-04-learn.md`。

  你把阈值改成 90% 分位数,当时想让它解决什么问题?
```

最后那一问只问一件你自己定过的事，可以不答。答了，它把你的话记进报告的「下一步」。

为什么要请你开口？动手前我们查过几项研究。一项 52 人的实验里，把思考整个交给 AI 的人学得最差，边用边追问概念的人没受影响；不过按用法细分后每组只有几个人，只能算初步证据。复盘有元分析撑着，平均能提升表现，那里的复盘是本人自己回顾、大家一起讨论。另有一项 704 人的预注册实验发现，事后提醒一句「你刚才怎么用的 AI」也有用，只是任务是分数运算，很窄。出处和细节见[调研记录](design/2026-10-15-导师插件-调研与讨论稿.md)的 3.3 节。

- 11-04 润色｜结论里的形容词换成表里有的数字和比较对象，用词强度跟证据强度对齐（卡 W11）｜这次：「significantly outperforms prior work」改成对稠密注意力和 token 剪枝的具体数字
