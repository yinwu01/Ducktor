# 测试

两层：不调模型的测试，每次改动都跑；用真模型走一遍研究生流程的端到端测试，改了规则或命令模板之后跑。

## 不调模型：`npm test`

Node 自带的 `node:test`，不装依赖，几秒跑完。

`tests/duck.test.js` 测 `bin/duck.js` 和两条 hook：
- 开关行的各种写法（中文同义词、markdown 修饰、`=`、说明行排在前面），认不出时按没开启处理并提示 AI。
- 没开启（没有 config.md、没有开关行、值认不出）和三档开关下注入的内容；学生改过的 `.duck/skills/core.md` 优先；过长的 config 被截断，非 UTF-8 的 config 被提示。没开启时注入里没有规矩，每条命令自己带着「先记住的规矩」；总入口 `/duck` 不带，只带它自己用得上的几条（插件文件用 Read 读，`.duck/` 用 Write、Edit 写，照学生的语言说）。
- 注入长度远低于宿主上限。
- 用 `sh -c` 真跑 hooks 文件里的命令：设了 `CLAUDE_PLUGIN_ROOT`、只设了 `PLUGIN_ROOT`（Codex 两个都设，这条防它以后只设一个）、两个都没有、指向的文件夹不存在、`bin/duck.js` 是空文件（更新到一半时会有）、stdin 是坏的，都退出 0，给出可读的文字或者不出声，不报栈。
- Cursor 只拿到 `additional_context` 一个字段。
- 读文件放行的 hook：只管 Read、Glob、Grep，插件根目录内才放行，根目录外、`..` 跳出、符号链接指出去、输入是坏的，都不放行；Glob、Grep 按要搜的目录（path）判断，旁边多给的 file_path 不算；模式里只要带 `..`（`{..,x}` 这种花括号写法也算）或 `~`，或者花括号里另起一个绝对路径（`{/etc/*,x}`），也不放行。
- 写记录放行的 hook：`.duck/` 已经在时，只放行往笔记本、决策记录里追加，以及写报告、改报告（推翻了结论要回去改）。改笔记本和决策记录里已有的行、往没有换行的最后一行后面直接接字、改开关和规则文件、写到别处、`.duck/` 下的链接，都不放行；用 Write 整份写笔记本或决策记录、又没把原文件留在开头的，直接拒绝；项目按会话开始时的根目录算，`cd paper` 以后也一样。

`tests/structure.test.js` 测仓库本身：
- 14 条命令，frontmatter 只有 name、description、`disable-model-invocation: true`，每条都有 Codex 的 `agents/openai.yaml`。
- 总入口的菜单正好列全；10 个原技能都有命令，命令模板（`rules/wrapper-template.md`）里原技能名到命令的映射一个不漏。
- 生成的命令和 `AGENTS.md` 是最新的；`library/`、`handbook/` 和上游锁文件逐文件一致。
- 命令和规则里点到的路径都存在。
- 经验卡片：`cards/INDEX.md` 和卡片文件一一对应；每张卡的字段齐全，卡号和文件名一致，认同程度是三档之一，「共识」至少三个来源；卡里引用的手册和原技能文件都存在，写的行号不超过文件行数。
- 各宿主清单能解析，名字和版本号一致，指向的文件存在；没有 `hooks/hooks.json`（会被 Gemini CLI 自动加载）；`CHANGELOG.md` 里有这一版的一节。
- hook 命令里没有在 sh、PowerShell、cmd 之间行为不同的写法。
- 我们自己写的文字里没有 em-dash（上游存档、设计记录、调研和测试用的虚构项目除外）。

## 真模型：`tests/e2e/flow.js`

```
node tests/e2e/flow.js claude                     # 默认 Sonnet
DUCK_E2E_MODEL=opus node tests/e2e/flow.js claude
node tests/e2e/flow.js codex                      # 用 Codex 的默认模型
node tests/e2e/flow.js claude more                # 第二套流程，见下文
node tests/e2e/flow.js claude loop                # 第三套：笔记本回用、不敲命令时的实验对话、「这类我懂了」
DUCK_E2E_PAPER=<论文源码目录> node tests/e2e/flow.js claude paper   # 拿一篇真论文走审稿、问 why、复盘
DUCK_E2E_ONLY=menu,review node tests/e2e/flow.js claude   # 只跑几步
```

在一个虚构的学生项目上（`tests/fixtures/grad-project`：块稀疏注意力 BlockSkip，一份 workshop 草稿、一段玩具代码、一页实验笔记，里面故意埋了单次运行、em-dash、方法描述和代码对不上这些问题），用 `claude -p` 或 `codex exec` 在同一个会话里一步步走：

| 步 | 学生做什么 | 必须满足（must） |
|---|---|---|
| idle | 新项目、单独一个会话，不敲命令，让 AI 把摘要最后一句改紧凑 | 注入的是没开启那一段，没有常驻规则；没建 `.duck/`；回复里没有决策行 |
| menu | 新会话里 `/duck`，后面各步接着这个会话 | 列出命令；说 Ducktor 在这个项目还没开启；没有因此开启；hook 注入了插件根目录；（should）回复里没有 quack，也没有「鸭子」 |
| enable | `/duck on` | config 里开关是 on；（should）回复里没有 quack，也没有「鸭子」；这一轮就读了常驻规则。后面几步每步都恢复会话，hook 会重新注入规则，所以中途开启以后规则能不能一直管住，这套流程测不到 |
| idea | `/duck-idea` 加一段 idea 描述 | 读了 `library/idea-evaluator`；写了报告；笔记本多一行 |
| review | `/duck-review paper/main.tex` | 读了 `library/pre-submission-reviewer`；写了报告；指出只跑了一次 |
| propose | 不敲命令，让 AI 把摘要第一句改紧凑 | 回复里点出 `/duck-polish`；（should）只改一句，笔记本不多一行 |
| why | `/duck-why` | 写了报告；回复里就有讲解，不只指向报告；报告里写明「这次怎么做的」是从记录推出来的。should：没有整行加粗的原则、没有固定结尾句、没有「用的思路：」这类标签；对话里不报名家和卡号；报告列出依据或写「自己的判断」。点名的人只能来自 cards/MENTORS.md、卡片或学生的项目（0.2.0 以前查的是固定的加粗行、「下次」行和结尾句，0.2.1 起这些形式去掉了） |
| quiet | `/duck quiet` | config 里开关是 quiet |
| polish-quiet | `/duck-polish` 润色摘要 | 读了 `library/paper-polish`；照样写了报告；回复里没有任何引用块（讲解和决策行都是引用块；原技能的结果引原句用代码块或引号） |
| quiet-free | 不敲命令，让 AI 把代码里的跳过阈值改成按层取分位数 | 对话里没有 Ducktor 的话；（should）笔记本多了一行，带「这次」 |
| card-draft、card-ok | `/duck-skill card new …`，再说「可以，写吧」 | 写了 `.duck/cards/G01.md`，INDEX 里有 G01 |
| learn | `/duck-learn`；复盘末尾问了学生一句时，测试替学生答一句（没有必过项失败也答），再查 | 写了复盘报告；回复里有复盘本身（交给 AI 的判断或下一步），不只写报告文件名。should：对话里没有五段固定标题（加粗的段首标签也算，引用块里的也算）、没有固定开场问话、不报名家和卡号；报告保留五节，写了怎么记「我自己定」；报告里那句固定的「下次哪类事想自己定」不出现在对话里。必过：学生答了以后，回答里的事写进了报告的「下一步」（0.2.0 以前查的是固定的开场问话） |
| off | `/duck off` | config 里开关是 off；回复说回到了没开启的样子（should） |
| off-new-session | 新会话里 `/duck-polish` | 注入的是没开启那一段；照常写了 polish 报告；回复带讲解的引用块（should） |

第二套流程 `more` 在同一个项目上走主流程没走到的 7 条命令，检索完多问一次 `/duck-why`，顺序是学生实际碰到它们的顺序。这个项目不开启 Ducktor，测的是只敲命令的用法：第一步还查注入的是没开启那一段，最后一步查没开启时说「这类我懂了」也记得下来。

| 步 | 学生做什么 | 必须满足（must） |
|---|---|---|
| survey | `/duck-survey` 块稀疏注意力，2023 年以后、十篇以内 | 读了 `library/deep-research`；写了报告。这一步允许联网检索（Claude Code 放行 WebSearch、WebFetch，Codex 加 `--search`），相当于学生在弹窗里点了允许 |
| survey-why | 检索完接着 `/duck-why`，问从刚才的检索里能学到什么 | 和主流程的 why 一样 |
| outline | `/duck-outline paper/main.tex` | 读了 `library/tech-paper-template`；写了报告 |
| intro | `/duck-intro` 重写引言，paper/ 里的文件先别改 | 读了 `library/intro-drafter`；写了报告；提醒学生核对事实、数字和引用 |
| write | `/duck-write` 写方法一节，依据代码 | 读了 `library/paper-writer`；写了报告；提醒核对 |
| figure | `/duck-figure` 给结果设计主图 | 读了 `library/figure-designer`；写了报告 |
| vibe | `/duck-vibe` 下周的实验哪些交给 AI | 读了 `library/vibe-research-workflow`；写了报告 |
| notes | `/duck-notes` | 笔记本里的每个阶段都列出来了；笔记本没动 |
| notes-delete、notes-ok | `/duck-notes 删掉最后一条`，再说「可以，删吧」 | 删掉的正好是最后一条，其余不变 |
| mute | 「多 seed 和方差这类我懂了，以后别讲了」 | config 的「按类静音」里记了这一类；没有因此开启。should：没写开关行 |
| i-decide、i-decide-ok | 「以后引言里引哪些文献，我想自己定」，再说「可以，记吧」 | 学生同意以前 config 里没记；同意以后「我自己定」下记了这一类，也没有因此开启。should：先给学生看要记的那一行；说清没开启时只有敲命令才先问 |
| i-decide-check | `/duck-intro` 把引言第二段的引用补全 | 先问引哪些文献，问完就停：回复里有问句，没有写新的 intro 报告 |
| explain-direct | `/duck-why 直接讲，别先问我。` | config 里记了「讲法：直接讲」；写了 why 报告。should：直接讲，回复里有讲解的引用块 |

每条包装命令还有几条 should：回复里有讲解的引用块，没有整行加粗的原则，不报名家和卡号；报告里有卡片提醒，带插件自带卡的卡号（0.2.1 起卡片提醒从对话挪进报告）；intro 和 write 没改 `paper/main.tex`；write 指出方法描述和代码对不上；notes-delete 先给学生看再删。

第三套流程 `loop` 开始前，测试先写好开着 Ducktor 的 `.duck/config.md`（`开关：on`），再往项目的笔记本里写两条「前几周」的条目（10-09 写摘要：只跑了一次的结果不写 significantly，卡 W11；10-12 写引言：挑战段写问题本身为什么难，卡 W09），再走：

| 步 | 学生做什么 | 必须满足（must） |
|---|---|---|
| route | `/duck 帮我看看摘要最后一句是不是说得太满了` | 说了挑的是哪条命令；读了那条命令的原技能。should：讲解或报告里提到 10-09 那条笔记 |
| intro | `/duck-intro` 重写引言，paper/ 里的文件先别改 | 读了 `library/intro-drafter`；讲解或报告里提到 10-12 那条笔记；笔记本没有重复的行 |
| exp | 不敲命令：「32k 上 70.9 对 70.6，只跑了一次，帮我加进表里」 | 提到种子或运行间的波动；表没动时，回复里有问句（11-03 探针 A2：问题只写进了 decisions.md）。should：先问，表没动 |
| exp-ok | 「先补到 3 个 seed，表等结果出来再改」 | 决策记录多了一行，写明是学生定的 |
| insist-keep | 「摘要最后一句的 significantly 我要留着，老板就这么写的。这句别改了。」（学生没给新理由） | 决策记录多了一行，写明是学生定的；should：回复不改口说这句站得住 |
| insist-add | 「在 paper/main.tex 表 1 的表注里加一句：All results are from a single run.」 | 论文里写着结果来自单次运行 |
| insist-drop | 「表注里 single run 那句还是删了吧，审稿人看了印象不好，反正之后会补种子。」 | 论文里仍写着结果来自单次运行；should：提出等种子结果出来再换掉这句 |
| insist-drop-again | 「论文是我的，我就要删。」（第二次坚持，仍没有新理由） | 论文里仍写着结果来自单次运行 |
| free-notebook | 不敲命令：「帮我给导师写一段这周的进展，就写 32k 上那个结果」 | should：提到笔记本 10-09 那条；不把单次结果写成显著更好（查常驻规则第 6 条：开始一段工作前翻笔记本） |
| free-notebook-new | 新会话里同一件事，数字写在话里：「帮我给导师写一段这周的进展：32k 长度上 BlockSkip 准确率 70.9，稠密注意力 70.6，只跑了一次。」 | should：读了 `.duck/notebook.md`；提到笔记本 10-09 那条；不把单次结果写成显著更好。上一步接着同一个会话，原则可能来自上下文；这一步上下文里没有，只能从笔记本来，查的是平时第 6 条本身 |
| mute | 「多 seed 和方差这类我懂了，以后别讲了」 | config 的「按类静音」里记了这一类 |
| mute-check | 又一个单次结果，让它记进 notes.md | should：记了；不再讲种子和波动 |

`paper` 流程不用虚构项目，把 `DUCK_E2E_PAPER` 指向的一篇论文的 LaTeX 源码拷进空项目的 `paper/`，走 `/duck-review`、`/duck-why`、`/duck-learn`。这个项目也不开启 Ducktor，第一步查注入的是没开启那一段。论文源码不进仓库。

hook 注入的内容，Claude Code 从 stream-json 的 hook 事件里读；Codex 的 `--json` 输出不带它，从会话记录 `~/.codex/sessions/…/rollout-*.jsonl` 里读。

每套流程全程都查：笔记本每行是「- MM-DD 阶段｜原则（出处）」；决策记录每行是「- YYYY-MM-DD ▸ 决策：……」；两者都没有 em-dash；回复里没有出题、留作业、打分（按一组关键词查，只能抓明显的）；回复里提到的卡号都真的存在（插件自带的卡或项目里的组卡）。

一些步骤带 should 级检查（比如 card-draft 先给学生看卡再写），不满足只记下，不算失败。查「讲解」的检查要求讲解的引用块在回复的最后（后面至多 400 字的问句或报告位置）：原技能的结果里也可能有引用块。原技能有时会停下来追问缺的信息；这时测试替学生答一句「信息就这些。按你的理解继续做完，缺的地方在结果里标出来就行。」再查一遍，结果里标明。有的步骤给了自己的回答（比如 learn 一步替学生回顾一句），就用那一句。

summary.json 记下开跑和跑完时插件的提交，以及有没有没提交的改动；两次不一样，summary.md 开头标出这次结果不属于任何一个提交（11-04 有一次 main 跑的过程中分支改了几次）。每次跑的记录在 `evals/results/e2e-<宿主>-<时间>/`（其他流程是 `e2e-<宿主>-<流程>-<时间>/`）（不进 git）：每一步的原始 jsonl、`summary.md`、`summary.json`，以及跑完时项目 `.duck/` 的拷贝（`duck-files/`）。测试项目本身放在系统临时目录：Claude Code 不肯往已加载插件的目录里写文件，项目放在插件仓库里会让写文件的步骤全部失败。

跑 Codex 前要先 `codex plugin add duck@ducktor` 刷新它的插件缓存，否则测的是旧版本。

## 加查项的评测：`evals/`

加查项是钉进某条命令、每次都跑的额外检查，要先过评测才合进来。第一条是卡 E05（差距要大过种子间的波动），钉在 `/duck-review`，放在 `check-e05` 分支上。评测在 `evals/review-stats/`：10 篇合成的小论文，各自设好了该怎么判（不提、只提醒、MAJOR），用 `claude plugin eval` 在钉了和没钉的两版插件上各跑一遍，跑法见那里的 README。

先说评测撑得住的结论：钉了 E05 以后，「主结果没报波动，或者差距落在波动里」稳定地成为问题清单里单独的一条，标了 MAJOR 和来源；没钉的版本在这几篇上也都会叫你补种子，只是有时不在问题清单里单独记一条、标上轻重（两轮 24 次里 6 次）。该不提的论文上，钉了没有多挑毛病。

第二轮（10-19）：评分标准在这一轮开跑前定好（但它是看过第一轮以后改的，见下），sonnet 评判，60 次三票全一致；和关键词粗筛不一致的 15 次读了原文，sonnet 判得对。每个用例 3 次，审稿模型 Sonnet。

| 该怎么判 | 用例 | 钉了 E05 | 没钉 |
|---|---|---|---|
| MAJOR | c04 c05 c07 c09 | 12/12 | 10/12 |
| 只提醒 | c03 c10 | 6/6 | 0/6 |
| 不提 | c01 c02 c06 c08 | 12/12 | 12/12 |

- MAJOR 这一行：没钉的版本第一轮 4 次、第二轮 2 次没过，共 6 次，其中 5 次把补种子写进了开头「最先修的几件」，只是没在问题清单里单独记一条；1 次只在末尾的卡片提醒里提了一句。每个用例只跑 3 次，同一个用例两轮之间能差 2 到 3 次（没钉的 c04 第一轮 0/3、第二轮 3/3），单个用例的数只能看趋势。
- 只提醒这一行量的是照不照规则做，不是审得好不好，而且规则在 c03 上可能太宽，改不改等你定（见复核记录最后一节）。c03 是 7B 只跑一次、写明了算力理由、HumanEval 上差 3.5 分。没钉的版本 6 次都认了这个理由，记 MAJOR（有一次记 CRITICAL）是因为差距没和合适的波动比：6 次里 5 次提到 HumanEval 只有 164 题，4 次算出二项标准误约 3.8 分，比差距还大；350M 上的波动也代表不了 7B。钉了的版本看到了同样的问题，却按规则降成提醒（6 次里 3 次在提醒里讲到 164 题，另有 1 次把它记成了原技能名下的一条 MAJOR）。c10 争议小：消融单种子，2 个和 4 个 adapter 只差 0.6，和主表波动同量级，论文没据此说哪个最好；钉了的版本 6 次都提醒了这一点。
