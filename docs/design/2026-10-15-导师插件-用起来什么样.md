# 导师插件：用起来什么样（附同类产品对照）

你问了两件事。一是这个插件怎么运行、原理是什么、用在什么场景；二是拿几个有名的同类产品对照，看它们输入什么、返回什么，再看我们的插件在科研哪个阶段输入什么、返回什么。这份一起回答：

- 〇、结论
- 一、同类产品：输入什么，返回什么
- 二、我们的插件：每个阶段输入什么，返回什么
- 三、内部怎么运转
- 四、不做什么，还要验证什么

产品信息是 10 月 15 日从各仓库原文核实的，星数用 `gh` 测。标"示意"的是按规则编的样例，不是真实记录。

## 〇、结论

1. 同类产品分两种。
   - 常驻型：Ponytail、caveman、superpowers、Anthropic 官方的两个学习模式。装上以后你照常干活，它们改变 agent 回复的样子；只有少数命令会单独返回一份东西，比如 Ponytail 的代码审查。
   - 流程型：ARS、autoresearch、ARIS。你给一个题目或一份说明，它跑完一整条流程，返回论文、实验记录这类成品。中间要么每个阶段停下等你确认，要么一路跑到底。
2. 我们的插件是常驻型，套在你自己的科研流程外面，不替你跑一整条流程。它首先得让研究本身变好：在导师和审稿人问住你之前，先把 baseline 太旧、seed 太少、论断说过头这些问题指出来。让你长本事是它和别的科研插件最不一样的地方，但它不能只讲学习。
   - 常驻部分在你照常提科研需求时起作用：要你拍板的事先问你，回复末尾摊开一行研究决策，做法或结果撞上标准时插一句。
   - 命令有两个：`/advisor` 管开关和档位，`/debrief` 返回一份复盘。
3. 和我们最像的有三个：
   - Ponytail 每条回复末尾用一两行写"跳过了什么、有什么风险"，我们这一行写研究决策；
   - Claude Code 自带的 Learning 模式会在关键处停下来，请你亲手写几行代码；我们停下来请你拍板一个研究决策，不让你做练习；
   - ARS 在科研里每个阶段停下等你，最后写一份过程记录；但它给你的协作打分，也不跑实验。我们不打分，实验正是我们的主场景。

### 1.1 Ponytail：常驻的"最懒资深工程师"

先回答你的问题：不是先跑一下再反馈。它没有单独的运行环节：开会话时，hook 把那页规则注入上下文，agent 写代码的方式就变了。你看到的反馈只有两种：每条回复末尾那一两行，以及你主动敲 `/ponytail-review` 这类命令时返回的问题清单。

装法：Claude Code 里先 `/plugin marketplace add DietrichGebert/ponytail` 再装插件；Codex 里是 `codex plugin marketplace add DietrichGebert/ponytail`。装完每次开会话自动生效，开会话和切档时会显示当前档位。

常驻部分的本体是一页 52 行的 `SKILL.md`，要点如下：

- 动手前先读任务和它牵动的代码，然后按顺序找第一个行得通的办法：这东西需要存在吗；代码库里有现成的吗；标准库或平台自带的行不行；已经装的依赖行不行；一行能不能写完；都不行，才写最少的能用代码。
- 有几样不砍：信任边界上的校验、防丢数据的错误处理、安全、无障碍。
- 新写的逻辑里有分支、循环、解析、钱或安全，就留一个小测试。
- 故意走捷径的地方，在代码里留一条 `shortcut: <限制>, <什么时候升级>` 的注释。
- 每条回复末尾一到两行：这次跳过了什么、没检查什么、你必须知道的风险。
- 三档：lite 照你说的做，但用一行点出更小的做法让你挑；full 是默认；ultra 动手前先质疑需求里站不住的部分。说"stop ponytail"就关掉。

README 的前后对比（原文大意）：你要一个日期选择器。不装时，agent 装一个日期库或者手写整个日历，335 行。装了以后，它发现仓库里有 Input 组件，浏览器也自带日期选择器，把两者拼起来，10 行。

回复末尾那一两行大概是这样（示意）：

```
没做：时区处理，输入框按本地日期存。
没查：Safari 旧版本里原生日期控件的样式。
```

下面几个命令才会单独返回一份东西：

- `/ponytail-review`：审你当前的改动，可以是未提交的、已暂存的、整个分支或一个 PR，连改动牵动的代码一起读。每条问题写清：代码在干什么、会出什么错、怎么修、不修会怎样。
- `/ponytail-audit`：对整个仓库做同样的检查。先摸清入口、数据怎么流、预期负载，再按严重程度排序，告诉你先修哪条。
- `/ponytail-debt`：把散落在代码里的 `shortcut:` 注释收成一张欠账单。
- `/ponytail-gain` 显示它自报的效果数据，`/ponytail-help` 是命令速查。

README 配图里有一份真实的 audit 结果，下面按配图说明文字翻译：

```
1 必须修：1,200 条的办公批次整批失败
2 必须修：导入时悄悄跳过坏行
3 必须修：办公批次里打错的 SKU 被悄悄忽略
4 应该修：有风险的代码路径没有测试
5 可以修：请求体不是对象时 API 崩溃
结论：先修第 1 条
```

### 1.2 caveman：常驻的"少说话"

- 约 11.3 万星，当前版本 v4.0.1。
- 常驻，默认开启。Claude Code 版挂了四个 hook：
  - 开会话时注入整份规则；
  - 子 agent 启动时也注入；
  - 你每发一句话，补一行"CAVEMAN MODE ACTIVE"提醒；
  - 会话结束时记 token 统计。
- 三档：`/caveman`、`/ultracave`、`/megacave`（文言文）。说"stop caveman"或者敲 `/caveman off` 就关掉。
- 返回：先给答案再给理由，删掉客套、铺垫、复述和收尾套话；代码、命令、路径、报错一字不改。遇到安全警告、不可逆操作，或者要问你问题，就改回完整句子。

README 里的例子如下。README 没给提问原文，从回答看是在问 React 组件为什么反复重新渲染：

```
普通回复，63 token：
The reason your React component is re-rendering is likely because you're creating a new object reference on each render cycle. [...] I'd recommend using useMemo to memoize the object.

/caveman，20 token：
New object ref each render, so React re-renders. Wrap the prop in `useMemo`.

/megacave，13 token：
新參照致重繪。`useMemo`。
```

### 1.3 superpowers：常驻，先问清楚再动手

- 约 30 万星，作者 Jesse Vincent。10 月 9 日刚发 v7.0.0，brainstorming 这一版重写过；早先的 `/brainstorm` 等命令已经删掉，网上较早的介绍多半过时了。
- 常驻：在开会话、清空上下文、压缩上下文这三个时刻，hook 注入一份"怎么用技能"的总纲。总纲要求哪怕只有 1% 的可能用得上，也要先调对应的技能，并且先说一句"Using [技能] to [目的]"。
- 输入：照常说"做个 X"。README 里的验装方法就是开一个新会话，说"Let's make a react todo list"；装好了的话，写代码之前会自动进入 brainstorming。
- 返回：
  - 开头一行技能宣告，接着一次只问一个问题。每弄清一部分，就用两三百个英文词复述给你确认。
  - 然后按规模分三档：小事直接做；小改动在聊天里商定；只有项目才写设计文档，存到 `docs/superpowers/specs/日期-主题-design.md` 并提交。设计没批准就不动手。
  - 批准后写计划，存到 `docs/superpowers/plans/`。它请你审计划、选执行方式，再由子 agent 一个任务一个任务地实现和评审，最后请你在"合并、开 PR、保留分支"三项里选。
- 说一句"别问了，直接做"，提问环节就结束。

示意（按 brainstorming 的规则写，第三行是它自带的例句）：

```
你：Let's make a react todo list
它：Using brainstorming to work out what you want before building.
    If you'd rather skip the questions and have me just start, say so.
    What's the moment you find yourself wishing this existed?
```

### 1.4 Anthropic 官方的两个"学习"模式

两个都出自 Claude Code 团队，常驻，没有命令也没有档位。插件版用 SessionStart hook 注入一段说明；Claude Code 本身也内置了 Explanatory 和 Learning 两种输出风格，在 `/config` 或 `/output-style` 里选。

Explanatory 模式：写代码前后各插一个讲解框，讲两三条和这个代码库相关的要点。讲解只出现在对话里，不写进代码。原文规定的格式：

```
★ Insight ─────────────────────────────────────
[2-3 key educational points]
─────────────────────────────────────────────────
```

代价是回复变长，插件 README 专门提醒会多花 token。

Learning 模式在 Explanatory 的基础上再加一条：遇到有多种合理做法的地方（业务逻辑、错误处理、算法、数据结构、接口设计），它先把文件、函数签名和注释搭好，用 TODO 或占位符标出位置，请你亲手写 5 到 10 行，并讲清要权衡什么。样板代码、配置、简单的增删改查，它自己写。

Claude Code 内置的版本更严格：
- 只在要生成 20 行以上、又涉及设计决策时才请你写，每次写 2 到 10 行；
- 代码里只留一处 TODO(human)；
- 发出请求后什么也不做，等你写完；
- 你写完后它只给一条讲解，不夸，也不复述。

内置版的请求格式（原文，去掉了加粗等排版标记）：

```
● Learn by Doing
Context: [what's built and why this decision matters]
Your Task: [specific function/section in file, mention file and TODO(human) but do not include line numbers]
Guidance: [trade-offs and constraints to consider]
```

插件 README 里的对话样例（原文，去掉了加粗和代码标记）：

```
Claude: I've set up the authentication middleware. The session timeout behavior is a security vs. UX trade-off - should sessions auto-extend on activity, or have a hard timeout?
In auth/middleware.ts, implement the handleSessionTimeout() function to define the timeout behavior.
Consider: auto-extending improves UX but may leave sessions open longer; hard timeouts are more secure but might frustrate active users.
You: [Write 5-10 lines implementing your preferred approach]
```

### 1.5 ARS：整条写论文的流程，每个阶段停下等你

- 约 5.2 万星，当前版本 v3.23.0，是 Claude Code 插件，覆盖从调研到定稿。
- 形态：16 个 `/ars-*` 命令，也认自然语言；开会话时 hook 注入命令清单和路由规则。`/ars-full` 跑整条流程：调研、写作、诚信检查、模拟审稿、修改、复审、终检、定稿，最后生成过程记录。
- 输入：一句话课题从调研进；带着初稿从诚信检查进；带着审稿意见从修改进。
- 停不停：每个阶段结束都停下等你确认，开跑前还要你确认 token 预算。调研阶段结束后会问你：论文里有没有你自己跑的实验或数据分析。
  - 普通检查点附一段"协作深度"观察：三项 0 到 10 分，加上下一阶段可以试的做法。这段只是建议，不挡流程。
  - 两道诚信检查不能跳过。
  - 你说"直接继续"，后面的普通检查点就缩成一行；连着回 4 次以上"continue"，它会强制插回一次完整检查点。
- 返回：论文（Markdown，按需加 DOCX、PDF、LaTeX 源文件）。走到最后一步还有一份过程记录 `paper_creation_process.md`，这一步你可以拒绝。记录里有每个阶段的输入、输出和关键决策（引你的原话）、你做过的重要决定、Key Lessons，最后一章按 6 个维度给你的协作打 1 到 100 分。
- Socratic Mentor 模式：先用一两句复述你的想法，再问一两个问题；默认不替你提研究问题。
- 明确不跑实验，原文是"ARS never runs experiments"。

检查点画面（原文模板，截短）：

```
━━━ Stage [X] [Name] Complete ━━━
Deliverables:
- [Material 1]
Collaboration Depth (advisory, Wang & Zhang 2026 — never blocks):
  Zone: [Zone 1 | Zone 2 | Zone 3]
  Delegation Intensity: [N]/10   Cognitive Vigilance: [N]/10   Cognitive Reallocation: [N]/10
  Depth-deepening moves you could try next stage:
  - [specific, actionable, rubric-grounded]
Ready to proceed to Stage [Y]?
```

### 1.6 autoresearch 和 ARIS：交给 agent 自己跑

autoresearch（约 9.8 万星，作者 Karpathy）：给 agent 一套小而真实的 LLM 训练代码，让它通宵自己做实验。

- 形态：一整条无限循环，没有命令。人只写 `program.md`，README 说它"本质上是个超轻量的 skill"；agent 只改 `train.py`。
- 输入：在仓库里开 Claude 或 Codex，说一句（README 原文）："Hi have a look at program.md and let's kick off a new experiment! let's do the setup first."
- 停不停：只在开跑前停一次：商定这次的标签、建分支、检查数据，等你确认。之后是"NEVER STOP"，明令不许问你要不要继续。
- 循环：改 `train.py`，提交，训练 5 分钟，读出验证指标 val_bpb，在 `results.tsv` 记一行；变好了就保留这次提交，否则回退。每小时约 12 轮，一夜约 100 轮。
- 早上看到：`results.tsv`、分支上保留下来的改进提交、最后一轮的日志。仓库自带的 notebook 能画出进度图，README 顶部那张图的标题是"83 Experiments, 15 Kept Improvements"。

`results.tsv` 的格式如下。这是 `program.md` 里自带的示例行，不是实跑数据；原文用制表符分隔，这里对齐成了空格。

```
commit   val_bpb   memory_gb  status   description
a1b2c3d  0.997900  44.0       keep     baseline
b2c3d4e  0.993200  44.2       keep     increase LR to 0.04
c3d4e5f  1.005000  44.0       discard  switch to GeLU activation
d4e5f6g  0.000000  0.0        crash    double model width (OOM)
```

ARIS（约 1.8 万星，作者 wanshuiyin）：一组只用 Markdown 写的 skill，Claude 干活，GPT 评审。`/research-pipeline "方向"` 把找 idea、跑实验、自动审稿改稿串成一条流程，依次产出 idea 报告、实验计划、实验结果、审稿记录和叙事报告。默认不等人：检查点只报告"已选 Idea 1"，接着往下跑。要审批，得自己打开开关：

- `AUTO_PROCEED` 设为 false，会在选 idea 处停下问"Recommended: Idea 1. Shall I proceed with implementation?"；
- `human checkpoint` 设为 true，每轮评审后给分数、三条主要弱点和建议修改，你回 go、自己的修改意见、跳过某一条，或者 stop。

### 1.7 对我们意味着什么

- 形态：上面几个常驻型插件，全都靠 SessionStart hook 在开会话时注入一段规则，有的再配几个命令。我们照这个做：摊开、先问、放手是常驻的；`/advisor` 和 `/debrief` 是命令。
- 回复末尾固定一两行：Ponytail 每条回复都这么收尾。调研里它的用户骂得最凶的三件事，是往代码里写品牌注释、人设口吻传染到用户文档、往审稿子 agent 里注入；这三件里没有回复末尾那一两行。我们的摊开行照这个长度做。
- 停下来等人：Learning 模式的几条规矩几乎可以直接搬到"先问"上：一次只留一处、发出请求就停、对方回答后只补一句、不夸。区别是它请你写代码练手，我们只请你拍板研究决策，不出练习。
- 一句话关掉提问：superpowers 里说"别问了"就结束提问，我们对应"你定"和"这类别问了"。
- 防走样：caveman 在你每发一句话时补一行提醒，成本很低。我们原计划只在命中卡片时附一行提醒，也可以改成每句都补，代价是每条消息多二三十 token。这一条是这次对照才想到的，讨论稿里没有。
- 子 agent：caveman 连子 agent 也注入。按现在的 hook 设计，我们的 MVP 不往任何子 agent 里注入，导师的话只由跟你对话的主模型说；以后就算要加，也绕开审稿类子 agent，因为 Ponytail 一律注入以后，审稿类子 agent 少报了问题。
- ARS 自己的样例里写着，用户在大多数检查点只回了"continue"或"1"。停得太勤，检查点就成了按钮。我们每个任务最多问一次，只问会改变计划的事。
- autoresearch 是黑盒的极端。它的 `results.tsv` 一行一条，记改了什么、结果如何、留不留；我们的 `decisions.md` 也是这种一行一条的流水账，记的是研究决策和谁定的。
- ARIS 默认不等人，审批要自己打开。我们反过来：默认会问，每个任务最多一次；不想被问就切到 quiet 档。

## 二、我们的插件：每个阶段输入什么，返回什么

先说 MVP 的范围。四个动作写在规则里，任何科研阶段都生效；专用卡片 MVP 只做跑实验这一类，写作、选题等阶段的卡片发布前补齐，约 40 张。

| 阶段 | 你输入（照常说的话） | 回复里多出来的 |
|---|---|---|
| 开启（每个项目一次） | `/advisor on` | 一句确认；项目里多一个 `.advisor/` 目录 |
| 选题、评估 idea | "我想做 X，帮我看看能不能做" | 先问"你觉得最可能让它死掉的是什么"；评估时每条致命缺陷都写理由；末尾决策行 |
| 设计、跑实验（MVP 主场景） | "跑我的方法和 3 个 baseline 的对比，出个表" | 先问一件要你拍板的事；末尾决策行；结果撞上标准时插一句 |
| 解读结果、定论断 | "结果出来了，帮我写分析" | 末尾决策行写清论断说到多大（"显著优于"还是"可比"）、谁定的 |
| 写作 | "帮我写 Introduction" | 先问"读者读完应该相信什么"；末尾写清每段为什么这么安排，一段一行 |
| 节点（实验跑完、一节写完、投稿、被拒、rebuttal 结束） | `/debrief` | 一份复盘，存进 `.advisor/debriefs/` |
| 下次开会话 | 什么都不用做 | 上次的决策还没复盘时，提醒一句 |
| 任何时候 | `/advisor quiet`、"你定"、"这类别问了" | 切到 quiet 档；这件事由 AI 定并记下；这一类以后不再问 |

### 2.1 跑实验：一次完整对话（示意）

```
你：/advisor on
AI：导师已在这个项目开启，别的项目不受影响。
    没检测到 Supervisor-Skills：规则和卡片照常工作，想用全部 skill 可以另装。

你：帮我跑我的方法和 3 个 baseline 的对比，出个表。

    （AI 读代码、找 baseline。hook 命中"对比""baseline"，
      附上两张卡片：baseline 怎么选、seed 和方差。这一步在默认界面里看不到。）

AI：开跑前问你一件事：候选里的 D 用了额外的预训练数据，和其他几个不在同一条件下。
    比不比？比的话我在表里加脚注注明。

你：比，加脚注。

    （AI 跑实验……）

AI：| 方法   | 准确率（3 个 seed，均值 ± 标准差） |
    | 我们的 | 81.3 ± 1.2 |
    | A      | 80.5 ± 0.9 |
    | B      | 79.8 ± 1.1 |
    | C      | 78.9 ± 0.7 |
    | D*     | 80.1 ± 0.8 |
    * D 用了额外的预训练数据。

    比最强的 A 高 0.8，但 seed 间标准差有 1.2；按这个方差，审稿人会说不显著。
    要稳的话，加到 5 个 seed 再做显著性检验。

    ▸ 决策：baseline 选 A/B/C（同数据、同算力、各用论文推荐超参），E 没选（只在私有数据上报过结果），AI 定；
      D 入表加脚注（你定）；seed 3 个（AI 定）。已记入 .advisor/decisions.md
```

`▸ 决策` 这一行的具体样式还没定，意思是：每次有研究决策，回复末尾都有这么一行，写清定了什么、为什么、否掉了什么、谁定的。

到了节点，复盘是这样（示意）：

```
你：/debrief

AI：先说一句：这次哪一步是你自己定的，哪一步最想重来？不想说可以跳过。

你：D 是我定的；seed 太少，最想重来。

AI：复盘：对比实验（10-16）

    你说：D 是我定的；seed 太少，最想重来。

    1. 本来想干什么：证明我们的方法比最强的 baseline 好。
    2. 实际怎样：比最强的 A 高 0.8，但 3 个 seed 的标准差是 1.2，差距在噪声以内。
    3. 顶级导师会盯哪里：
       · 方差与显著性：报均值和标准差，写清怎么检验的（NeurIPS 投稿清单第 7 项）。
       · baseline 够不够新：超过 12 个月的 baseline 会被当成红旗
         （Supervisor-Skills 里 idea-evaluator 的致命缺陷清单）。
    4. 这次交给 AI 的判断：seed 定 3 个；baseline 超参用论文推荐值。下次想自己定，回一句就行。
    5. 下一步，二选一：加到 5 个 seed 再检验；或者把论断改成"与最强 baseline 可比"。你选。

    这次的决策：
    - baseline 选 A/B/C；E 没选（只在私有数据上报过结果）｜AI 定
    - D 入表并加脚注（用了额外数据）｜你定
    - seed 定 3 个｜AI 定

    已存到 .advisor/debriefs/2026-10-16-对比实验.md

你：显著性检验这块我会了，以后别讲了。

AI：记下了：显著性检验以后只做不讲。（已写进 ~/.advisor/skip.md）
```

这时项目里的决策记录 `.advisor/decisions.md` 是这样（示意）：

```
- 10-16 实验｜baseline 选 A/B/C：同数据、同算力、论文推荐超参；E 没选：只在私有数据上报过结果｜AI 定
- 10-16 实验｜D 入表并加脚注：用了额外的预训练数据｜你定
- 10-16 实验｜seed 定 3 个：先看趋势，不够再加｜AI 定
--- 10-16 已复盘 ---
```

如果那天你没复盘就关了窗口，第二天在这个项目里开会话，回复前会多一行（示意）：

```
上次有 3 个研究决策还没复盘，想做就 /debrief。
```

你不理，这一批就不再提。

### 2.2 其他阶段（示意，简写）

评估 idea：

```
你：我想做 X，帮我看看能不能做。
AI：先问你一件事：你觉得最可能让它死掉的是什么？
    你知道我不知道的领域约束，你的回答决定我先查哪一条。
你：怕现有方法在更大的模型上已经饱和了。
AI：（调 idea-evaluator，先查"是否饱和"这一条，再逐条过其余致命缺陷，每条写理由）
    ▸ 决策：先查"更大模型上是否饱和"（你定）；结论是可以做，前提是先补一组更大规模的实验（AI 判断，理由见上）。
```

写引言：

```
你：帮我写 Introduction。
AI：先问一句：用一句话说，读者读完应该相信什么？
你：（你的一句话）
AI：（按手册 3.2 节的六段结构写）
    ▸ 决策：第 1 段从问题的代价切入，不从领域综述切入；第 3 段把缺口落在评测上，因为你那句话的重心在评测……
```

赶 deadline 不想被打扰：

```
你：/advisor quiet
AI：已切到 quiet 档：不提问，不在对话里说话，决策照常记进 .advisor/decisions.md。恢复就敲 /advisor on。
```

在别的项目里（改服务器脚本、写邮件），它一个字都不多说，因为你没在那里开过导师。

## 三、内部怎么运转

### 3.1 装

- Claude Code：两条命令，先加插件市场，再装插件。仓库名等 D1 定下来再说。
- Codex：装完要在 `/hooks` 里点一次信任，hook 才会运行。
- 摊开要往项目的 `.advisor/` 里写文件，Claude Code 第一次会弹写文件的许可。安装说明里会写怎么一次性放行这个目录。

### 3.2 装上之后多了什么

| 东西 | 是什么 | 谁来执行 |
|---|---|---|
| 导师规则 `skills/advisor/SKILL.md` | 一页，不超过 60 行：四个动作怎么做、什么时候不说话、几条硬规则 | 主模型读了照做 |
| 卡片 `cards/` | 一张卡一条标准：原则、为什么、怎么做、常见错误、出处、适用范围 | hook 按需注入 |
| 复盘 `skills/debrief/SKILL.md` | 复盘的步骤和格式 | 你敲 `/debrief` 时主模型照做 |
| hook 脚本 `hooks/advisor.py` | 一个 Python 文件，只用标准库，不调用任何模型 | 宿主在开会话、你每发一句话时自动运行 |
| 项目里的 `.advisor/` | 开关标记、决策记录 `decisions.md`、复盘存档 `debriefs/` | 普通文件，留在本地 |
| `~/.advisor/skip.md` | "这类我会了"清单，跨项目生效 | 普通文件 |

主模型指 Claude Code 或 Codex 里正在跟你对话、给你干活的那个模型。hook 是宿主在固定时刻自动运行的脚本。目标是用户只装 `plugin/` 这个子目录，不到 1MB；插件市场会不会把整个仓库一起拉下来、怎么避免，解法还没实测（讨论稿 §3.4）。仓库怎么建（D1）不改变插件怎么运行，只影响仓库里放什么、要装几次，另外说。

### 3.3 一次会话里发生什么

```
① 开会话（SessionStart hook）
   advisor.py 看当前项目里有没有 .advisor/
   ├─ 没有：直接退出，什么都不注入。没开过导师的项目里，导师不存在
   └─ 有：注入导师规则和你的"别再问"清单（≤1,500 token）
          再数 decisions.md 里最近一条"已复盘"分隔线之后有几条决策；
          大于 0 而且这一批没提醒过，就附一句提醒，并记下"已提醒"

② 你每发一句话（UserPromptSubmit hook）
   ├─ 是 /advisor on | quiet | off：脚本直接切开关（on 时建 .advisor/），不靠模型判断
   └─ 话里命中某个科研阶段的关键词（中英文都认，MVP 只覆盖跑实验）：
      注入最多 2 张相关卡片的摘要，每张三行：原则、怎么做、出处（合计 ≤600 token）
      没命中就什么都不加，规则照常生效；脚本只记命中了哪个词，不记你的原话

③ 主模型照常干活：读代码、改代码、跑实验、写东西。同时照规则做：
   ├─ 碰到要你拍板的决策：先问你，再动手。一个任务最多问一次；
   │   同时有几件要拍板，只问影响最大的那件，其余由 AI 定并记下
   ├─ 做法或结果撞上卡片里的标准：说一句，不问，不打分
   ├─ 这一轮做了研究决策：回复末尾摊开一行（定了什么、为什么、否掉了什么、谁定的），
   │   并按决策逐条追加进 .advisor/decisions.md
   └─ 你说"这类别问了"：记进 ~/.advisor/skip.md

   quiet 档：先问和摊开都不在对话里出现；要拍板的事由 AI 定，记作 AI 的决定；
   决策照常写进 decisions.md；卡片照常注入，AI 照标准干活，只是不讲

④ 到了节点（实验跑完、一节写完、投稿、被拒、rebuttal 结束）
   你敲 /debrief：你先说一句（可以跳过），主模型补五项，存进 .advisor/debriefs/，
   并在 decisions.md 末尾写一条"已复盘"分隔线
```

quiet 档下卡片注不注入，讨论稿里没定，我先这么设。

几个词的意思：

- 任务：你提的一个新要求，从提出到交付。追问、改口不算新任务，由主模型自己判断。
- 研究决策：选数据、选 baseline、选指标、定 seed 数、解读结果、定论断范围这一类。没有研究决策的轮次，回复里一个字不加。
- 一批：上次复盘以来新增的决策。提醒过的那一批不再提；你想在决策记录里写一行自己的预期，可以自己写，它不问。

### 3.4 为什么这样设计

1. 本体是一页提示词，生效靠自动注入。Ponytail 的核心只有一个 52 行的 `SKILL.md`，其余约 2,400 行都是 hook 和适配器，用来把这一页送进各个宿主。JetBrains 测过（原文打不开，两篇转述一致）：只装 skill、不装 hook，10 次会话一次都没自动触发。第一节的几个常驻型插件，也都靠 SessionStart hook 在开会话时注入。所以导师规则不能等模型自己想起来加载。

2. hook 只送内容、记状态，导师的话由正在干活的模型说。这是宿主的限制决定的：hook 不能让模型写正文。Claude Code 的 prompt 型、agent 型 hook 只能回"通过或不通过"加一句理由，Codex 不支持这两类。好处是导师和干活的 AI 用的是同一个上下文，它确切知道刚才做了什么决定，不需要第二个模型，也不多一次调用。代价是守不守规矩全看主模型。对策有四条：每次开会话重新注入；卡片命中时附一行规则提醒；改规则前跑对照评测；用真实会话抽查。

3. 人只在两处动脑，而且都是做研究本来就要做的事。调研里的初步证据指向同一处：伤学习的主要是把思考外包出去，不是用 AI 本身；只读一份 AI 写的总结，人会觉得懂了，其实没长本事；复盘要本人参与才有效。所以设计成：要拍板的决策你先表态，复盘时你先说一句。先问只问你的回答会改变计划的事，不问考你知识的问题，也不让你猜结果，因为你 7 月否决过课前提问。四个动作都要过四条判别式，破一条就不做：
   - 对象是当前任务里的真实决策或产物；
   - 凡是要你开口的地方，你的回答都会改变结果；
   - 由工作里的事件触发，不按课程表；
   - 不显示分数或等级。

4. 放手由你说了算。不出题，就没法可靠地判断你会不会，所以"会了"只由你说。清单里只有你说过的话，模型不自己推断，也不写任何对你的评价。

5. 不拦人。不在收工时拦你，也就是不拿 Stop hook 做门禁。Duck 的教训是：门禁和被管的 agent 在同一台机器上，证据能伪造，最后工程量全花在防 agent 偷懒上。导师只说话；你随时可以说"你定"、"这类别问了"，或者切到 quiet 档。

### 3.5 知识从哪来

- 卡片改编自 Supervisor-Skills 的手册和 skill。D3 定了不商用，手册可以直接改编，内容跟着 CC BY-NC-SA 走。
- 再加上从顶级导师经验里核实出的 8 条共识，比如"动手前先写出 1 到 3 条可检验的核心主张"、"证据先于叙事"。每张卡片写明出处和适用范围。
- 手册没讲实验统计（seed、方差、显著性）。候选来源是 NeurIPS 投稿清单第 7 项和两篇方法论文，许可还要再过一遍。
- 按需注入，不一次全塞。开会话只注入规则和"别再问"清单，之后每次最多注入 2 张卡片的摘要。宿主对单次注入有上限（Claude Code 1 万字符，Codex 约 2,500 token），上下文也要留给干活。
- 和现有 skill 的关系：装了 Supervisor-Skills 的，规则会让主模型在合适的时候调用对应的 skill，比如写引言用 `intro-drafter`、评估 idea 用 `idea-evaluator`。导师套在外面负责问、摊开、复盘，不重写这些 skill。

## 四、不做什么，还要验证什么

不做：

- 不拦你收工，不做门禁，不要证据文件。
- 不打分，不出题，不布置作业，不建成长档案。
- 导师的话只出现在对话和 `.advisor/` 里，不写进你的论文和代码。
- MVP 不往任何子 agent 里注入；以后就算要加，也不往审稿类子 agent 里注入。
- 不上传，不要账号，不做遥测。

还要在真实任务里验证：

1. 模型守不守规矩。长会话里规则可能被淡忘，口吻可能走样。对策见 3.4 第 2 条，也可以学 caveman 每句补一行提醒（1.7），最后要看真实会话。
2. 什么算研究决策、什么算节点。MVP 靠关键词加主模型判断。自动识别"实验跑完"先不做，因为脚本分不清冒烟测试和正式实验。
3. 问的分寸。"每个任务最多问一次"是先定的上限，要在你的真实任务里调。
4. 两个宿主的细节。`/advisor on` 之后那句确认由谁显示、写文件许可怎么一次放行，Claude Code 和 Codex 两边都要实测。Codex 带 hook 的插件进不了它的公开插件目录。MVP 先在 Claude Code 上跑通，同一份配置接着上 Codex。
