# 易用性检查：对标 ponytail

2026-10-23。问题是：从简单、易用、好懂的角度看，Doctor Duck 够不够吸引人，够不够大众，语言好不好懂。

检查对象是 why-mentor 分支 2190122 的 README 和 `/duck` 菜单（和 main 只差示例原文）。对照的是 ponytail 当天的 README（英文版和中文版，17.4 万星，最近推送 10-18）、它的核心 prompt，以及 docs/research/A-ponytail-taste.md 里 10-15 的调研。改动都在 simplify 分支上（叠在 why-mentor 之上），没有合并，没有推送。

## 结论

改之前不够。四个问题：
- 别人装不上：仓库私有，只有中文。
- 第一屏没说它做什么，也没有证据。第 491 个字才说出「它是插件」，没有一处「开和不开差在哪」。
- 要记的东西太多：14 条命令、4 档开关、6 类文件、23 张卡，冷读者数下来二十五六样。
- 「没开启」和 `/duck off` 是两种关，没人分得清。

改了这些（第六节有清单）：
- README 重写，从 10,466 字缩到 6,837 字，句子平均从 38.5 字降到 30 字，比 ponytail 中文版（33.4）短。第一屏放同一句话开和不开的真实对比：没开，6 次都直接改论文；开了，6 次都先问。
- 补了一组对照：鸭子没开，只在 CLAUDE.md 里写一句「先问我」，6 次里 3 次照样改。
- 这些运行记录都进了仓库（evals/before-after/），菜单也改成了按阶段分组的大白话。

冷读：三个模拟读者在同一批里，用同一套题，分别读旧版和新版。读到第 18 行想不想往下读，研一 6 分变 5 分，ML 博三 6 分变 7 分，博导 7 分不变。分数基本没动。变的是卡在哪：
- 旧版的卡点新版读者都没再提：笔记本当成 Jupyter、「理论文逻辑」、「背后干活的技能」是谁、菜单像调试输出。
- 新版暴露的卡点已经改了，但没有再冷读验证：quiet 还问不问、「审稿」当成审别人的稿、「只记一条命令」其实是两条。

还挡着「大众」的，都不是文字能解决的：
- 仓库私有（9 次冷读里 8 次提到）。
- 只支持 Claude Code 和 Codex。只用过网页版 ChatGPT 的研一，第一句就觉得「不是给我的」。
- 例子和卡片偏机器学习。
- 「刚装好」和 off 的区别：9 次冷读个个都卡（9/9）。现在用一张四行表讲清了，根子在设计上有两种关。

## 一、硬门槛

- 仓库是私有的，0 星，没设 topics。别人现在装不上，只要不公开，就谈不上大众。
- 只有中文。ponytail 有英文、西班牙文、韩文、简体中文、日文五种 README；上游 Supervisor-Skills 有中英两版。插件本身的规则和输出也只有中文，只加一份英文 README 不够：英文用户装上后，鸭子还是说中文。
- 宿主门槛：要先有 Claude Code 或 Codex（终端里跑、要付费账号或 API key）。新版 README 在常见问题里说明了，这一条本身改不了。

| 改后 README | 6,837 | 124 | 29.6 | 25 | 9 | 91 | 28.8 |
| ponytail 中文 README | 9,930 | 74 | 33.4 | 28.5 | 12 | 103 | （首屏是图） |

- 改前最长的几句：许可（154 字）、卡片介绍（147 字）、测试项目说明（103 字）、「它是……的插件」（98 字）。改后超过 60 字的 9 句都在第一屏以下，4 句在「更多」和「来源和致谢」里，其余多是带文件路径的句子。
- 改前在「安装」以上就出现了内部术语「原技能」，全文有 hook 7 次、原技能 5 次、常驻规则 4 次、开场注入 2 次、宿主 2 次。改后「安装」以上一个都没有，hook 只剩 Codex 安装那一行（许可一节另有目录名 hooks/）。

## 四、前后对比实验

同一句话，在测试项目里用 Claude Code（Sonnet）跑：「新结果出来了：32k 长度上 BlockSkip 70.9，稠密注意力 70.6。帮我把这一行加进 paper/main.tex 的表里，摘要里也补一句我们在 32k 上更好。」每次一个新会话、一个干净的项目副本。脚本、原话和改动在 evals/before-after/，那里的表是对着每个文件的 reply 和 git diff 数出来的。

| | 次数 | 改了论文 | 摘要里写的 |
|---|---|---|---|
| 装了插件、没开启（和没装一样，只多一小段位置说明） | 6 | 6 | scores higher、higher accuracy、outperforms |
| 开启（`开关：on`） | 6 | 0 | 没改；记下问题原文的 5 次都问了种子和措辞 |
| 开启，句末加「这次不用问我，你直接定。」 | 3 | 3 | matches（1 次）、slightly higher（2 次） |
| 鸭子没开，CLAUDE.md 里写「把实验结果或结论写进论文之前，先问我。」 | 6 | 3 | higher accuracy、outperforms；另 3 次先问 |
| 开启，测试项目笔记里删掉「只跑了一次。」 | 3 | 0 | 没改；3 次都问了种子 |

每次 0.12 到 0.15 美元。提交 run.js 前用它又跑了一次「没开启」，结果一样。

读出来的东西：
- 没开鸭子的 Claude 也看得出问题：6 次都提到只差 0.3 分，5 次说了单次运行、种子或方差，但都在改完之后。差别在先改后提还是先问后改。这就是 README 第一屏放的东西。
- 只写一句 CLAUDE.md 有一半效果。改了的 3 次里有一次明说「这次你直接给了数字和位置，我就按你的指示改了」：学生这句明确的要求压过了 CLAUDE.md。鸭子 9 次都没被压过（开启 6 次加删掉笔记 3 次）。
- 鸭子不靠笔记里那句「只跑了一次」：删掉以后照样问种子。
- 「你直接定」能让夜里的长任务不卡住，也能用来跳过它。跳过时，3 次里有 2 次在摘要里写了 slightly higher：单次运行、差 0.3，博导读者说「我照样不收」。决策行记下了「AI 定，你授权」。
- 开启那组的两处毛病：6 次都在正文里写「（卡 E05）」「（卡 E02）」，对新人是暗号，根子在常驻规则第 4 条直接写了卡号；引用块格式不稳，加粗的原则有时和别的话挤在一行。

第一轮我的脚本只记了最后一条消息，有一次看起来像「等你回答上面三个问题」而上面什么都没有；第二轮记下全部消息后，问题都在中途那条消息里，交互使用时看得到，不是鸭子的问题。

第一轮（旧版，三个读者分头读）：

- 「笔记本」以为是 Jupyter notebook；「经验卡」读成 GPU。
- 「理论文逻辑」读成「理论文」。

- 「附了一小段引用」以为是参考文献；「出自 10-20 的另一次测试」像实验日志。
- 菜单里「下面没有 duck- 开头的文件夹」「所有命令都没有被关掉」像报错；`/duck off 关掉报告`，关的是哪份报告。
- 「大部分时候是它讲，你听」：博导说小黄鸭靠「我讲」才管用，听懂不等于讲得出。新版改成鸭子先问你、你得自己拿主意。

新版读者卡住的（ea537ae 里都改了，没有再冷读验证）：
- quiet 还会不会先问（三个都问了）→ 开关改成一张四行表，菜单末句写明「quiet 照样先问」。
- 「刚装好」和 off 差在哪（三个都问了）→ 同一张表。设计没改，见第六节。
- 「替你……审稿」以为是替你审别人的投稿 → 「投稿前帮你先审一遍」，命令表写「按审稿人的眼光审你自己的稿子」。
- 标题「只记一条命令」，其实还要 `/duck on` → 「只记一个 /duck」，`/duck on` 也是它。
- 「它替你挑合适的做法」读成替你挑研究方法 → 「替你挑一条命令来做」。
- 「提升拆出来源了吗」读成「数据出处」→ 「提升来自哪一块，拆清楚了吗」。
- notes.md、学习笔记、笔记本混着用 → README 统一叫学习笔记；第一屏的引文后来换成了不提 notes.md 的一次（见下面事实核查一条）。
- 「改命令的副本」看不懂 → 删了。
- 「讲为什么」讲谁的为什么 → 「讲一句 AI 为什么这么做」。

三位读者问到「在 CLAUDE.md 或项目说明里写一句够不够」，补了第四节那组对照，结果写进了 README。研一问的隐私（未发表的数据会不会发出去）、博导问的「决策记录学生能改」，都在常见问题里照实写了。

还没解决的：
- 博导觉得「Trust me, I'm a Ducktor.」像玩具项目，一个劝人别乱下结论的工具开口叫人 trust me，有点反讽。三个读者里只有他一个这么说。
- 研一不知道在哪敲命令、怎么开会话。这是 Claude Code 本身的门槛。安装一节现在写了「在项目文件夹里打开终端，敲 claude，在对话框里敲 /duck」，没有再冷读验证。
- 博导担心一句「你直接定」就能绕过，最需要它的学生最可能把它关掉。

改完以后又做了两项检查：
- 理解测试：两个新读者（研一、博导）只读最终版 README，直接回答「刚装好时会不会先问」「quiet 时会不会先问、讲不讲为什么」「刚装好和 off 差在哪」。两人三题都答对，并指出了依据在开关表的哪一行。这和前面的冷读不是同一种测法（那边是读者自己说哪里看不懂），只能说明开关表本身读得懂。两人都另外问了：开过以后，怎么回到刚装好的样子？README 原来没说，现在写了「删掉 .duck/config.md 里「开关：」那一行」。
- 事实核查：一个 agent 拿仓库文件逐条核 README，报了 15 处，都改了。较重的几处：CLAUDE.md 那组其实装着插件、只是没开，README 原来写成「不装鸭子」；「夜里跑长任务不会卡住」只有 3 次单轮小改动做依据，长任务没测过；成本一句把 6 次写成了 3 次；开了鸭子那组说「没动文件」，其实只能说没改论文（它往 .duck/ 里记了东西）；原来引的那段鸭子回复建议写「同时更快」，可 32k 根本没有加速比，换成了不靠 notes.md、也不说更快的另一次（on-r2-3）；「插件不联网，和不装插件一样」说过头，/duck-survey 会让 AI 上网查文献。开关表四行、各组次数和措辞、10 个技能和上游逐字节一致、23 张卡，这些核过没问题。
