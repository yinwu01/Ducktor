这一版经过两轮独立红队审阅，按意见改过（v0 和两轮审阅原文都在附件目录：`讨论稿-v0.md`、`红队审阅-第1轮.md`、`红队审阅-第2轮.md`）。和 v0 比，主要变化：复盘改成你先说一句，"放手"改成你说了算，MVP 砍到几天能跑通的大小，去掉了 Stop hook 拦人。只想批注的话，读 §〇、§4.3 和 §5 就够。

## 〇、一页结论

**你要做的**：研究生用 AI agent 做科研时，往过程里嵌一位导师。AI 照常干活；导师让过程不再是黑盒，在关键处按顶级标准把关，让人在真实工作里长本事。

**Professor Goose / Duck**：后来改名 Professor Duck，GitHub 私有仓，0 星，7 月 20 日起没再动过。问题不在代码，在方向和重量：
- 它管的是 agent，没管人；
- 旗舰放在 LaTeX 排版上；
- 10 个命令、3 个系统依赖、只支持 Claude Code、仓库 36MB。

值得带走的是几条结论，不是代码。删之前要先补一个备份：现有的 bundle 不含当前 HEAD。

**调研里最影响设计的五条**：

1. **Ponytail（164k 星）的本体只是一页 52 行的提示词。** 它能生效，靠 hook 在每次会话开始时自动注入；JetBrains 测过，只装 skill、不装 hook，10 次会话一次都没触发。它赢在人设、诚实和克制，机制本身不是原创。所以我们的本体也应该是一页导师规则。
2. **这个空白目前看是真的。** 在查到的范围内，没有项目同时做到四件事：嵌进包括实验的真实科研流程；在研究决策上把判断交还给人；里程碑复盘但不打分；你说"这类我会了"就跨会话不再管。最接近的 academic-research-skills（52k 星）在写作阶段也摊开决策、也会提问，但给人打分、不跑实验、没有"放手"。
3. **学习证据（四项主要研究的原文或摘要都核过）。** 初步证据指向同一个方向：伤学习的主要是把思考外包出去，不是用 AI 本身。事后照一下"你刚才怎么用的 AI"有用，积分奖惩没用；有效复盘的证据都来自本人参与的复盘。所以人至少要在两处动一下脑：要拍板的决策先表态，复盘时先说一句。都不打分。
4. **技术上目前看轻量可行，安装体积的解法待实测。** Claude Code 和 Codex 能共用一份 hook 配置（文档支持，Ponytail 已这么做）；hook 里不能让模型写正文，复盘只能由主模型在会话里写；继承署名靠 subtree 或 fork，`Co-authored-by` 不算数；安装体积有两条候选解法，都待实测。
5. **顶级导师语料核实了 49 条来源。** 其中 8 条共识可以当硬标准，补上手册里局限性、组会报告、读博元技能这几块空白。实验统计（seed、方差、显著性）在手册和这 49 条里都没有，要另补来源。（10-16 勘误：49 条里的 #25 调参手册其实有一节讲不同随机种子之间的波动，见 10-16 附件 I §6。）大部分来源只能转述加链接；NC 条款要提前想清楚。

**方案**：
- 一页导师规则，只在你开启过的项目里注入，别的会话不打扰。
- 四个动作：
  - **摊开**：有研究决策的那一轮，回复末尾一行写清决定了什么、为什么；
  - **先问**：只问要你拍板的决策，每个任务最多一次；
  - **复盘**：里程碑处你先说一句，导师再补，不打分；
  - **放手**：你说"这类我会了"，它就不再管。
- MVP 只做跑通场景一（跑对比实验）需要的：一页规则、2 个 hook、`/debrief` 和 `/advisor` 两个入口、6 到 8 张卡片。架构从第一天按"插件只是仓库里的一个子目录、两个宿主共用一份配置"来定。

**要你现在定的四件事**：
- D1 仓库放哪（新仓，还是直接长在 Supervisor-Skills 里）；
- D2 挂在谁名下；
- D3 要不要给商业化留口子（决定能不能直接改编手册）；
- D4 学习循环的强度。

**怎么讨论**：你在 §4.3 的四个场景上批注（尤其场景四：不顺的时候），回复 D1 到 D4；我出 2 页 spec 和仓库骨架，把场景一跑通；再在你一个真实任务上跑一次，对着真实输出改。

## 一、我对你想法的理解

### 1.1 你的四条架构要求

| 你说的 | 我理解的具体含义 |
|---|---|
| 1. 足够轻量，容易适配 | 内核是文本（一页导师规则 + 卡片）；hook 只负责在对的时候把对的内容送进上下文，不拦人、不做门禁；用户机器上只需要 Python 3；Claude Code 和 Codex 都能装 |
| 2. 最顶级标准的专业指导，收集哈佛、MIT 等导师的经验 | 导师说的每一条都有出处：Supervisor-Skills 手册 + 顶级导师公开的文章和讲稿。多位导师共同强调的当硬标准，有分歧的标明是哪家的看法 |
| 3. 结合现有全部 skill | 不重写 skill。卡片从手册和 skill 里提炼并注明出处，随插件走；装了上游 skill 的，干活时直接调用；导师层套在外面，负责摊开、提问、复盘 |
| 4. 继承关系（新仓库的 contributors 里显示原作者） | 两层继承：git 层导入上游历史，保留署名；内容层引用上游 skill，上游改进能直接流进来 |

### 1.2 三处我想先挑明的张力

1. **"告诉你学到了什么"本身不产生学习。** 只读一份复盘，人会觉得懂了，其实没长本事（§3.3）。学习需要人在关键处自己动脑。可你 7 月明确否决过上课：没有 quiz、没有课前提问、没有布置作业、没有"成长档案"叙事。两者要同时成立，就只能让人动脑的那一下恰好是做研究本来就该做的事：拍板一个真实决策，或者复盘时说一句自己的判断。§3.3 给了判据，§4.2 按它设计。
2. **新开仓库，还是在 Supervisor-Skills 里长出来。** 新仓库有独立品牌，但从 0 星起步，要靠 subtree 继承署名，还要把上游历史连同约 52MB 的文件（大头是一个 16.6MB 的讲义 PDF 和一批图片）导进仓库，当前文件树可以再瘦身（§3.4）。在 Supervisor-Skills 里加一个插件目录，署名和分发都是现成的，但归组织管。§5 的 D1 把两边摆开了。
3. **"顶级标准"和骆老师手册的个人风格冲突时听谁。** 收进哈佛、MIT 导师的经验以后，必然有和手册不一致的地方。我的默认是先并列、不裁决，裁决规则等你和骆老师谈过再定（D7）。

### 2.2 为什么说它不行：我的诊断

问题不在代码质量（测试用真产物，边界写得诚实），在方向和重量。

1. **重心放错了：管 agent，不育人。** 7 月 4 日 v1 spec 写的差异化定位是"别的工具优化产出，Professor Goose 同时优化使用它的人"。建完以后，README 开头介绍的是"给 LaTeX 论文项目用的 Claude Code 插件……用 hooks 检查写作、排版、审稿、配图这些任务有没有走完约定的收尾步骤"。导师复盘沦为门禁的一项义务：门禁只核验 `.duck/reports/` 下有没有一个大于 200 字节的 HTML。工程量几乎全花在防 agent 偷懒上。
2. **旗舰选在了最不需要导师的地方。** 旗舰是 LaTeX 排版（编译、渲染、逐页看三轮）。排版是体力活；研究生在 vibe research 里最缺的是判断（选题、实验设计、结论能说到多大），这些 Duck 基本没碰。
3. **太重。** 10 个命令；合同、证据 JSON、时间戳、逃生舱一整套概念；3 个系统依赖；只跑在 Claude Code；仓库 36MB。和"轻量、易适配"正好相反。
4. **门禁兑现不了承诺，只好写长免责。** 审计 F7：门禁和被门禁的 agent 在同一台机器、同一个信任域，证据文件和时间戳都能伪造。于是 README 首屏是一大段"先说清边界"，读起来是防守姿态。
5. **先造后看。** 第一份能放进 README 的真实收据是 07-18，开工两周之后（07-10 做过两次内部验证实验）。定位辩论打了 6 轮，前后用过 4 个名字。用户体验是最后才见到的东西。
6. **导师的知识很薄。** 专业内容基本只有手册里排版、作图、审稿的清单，没有你这次说的"顶级导师经验"这一层。

## 三、调研

五路并行调研，原始报告在同级目录 `2026-10-15-调研附件/`（A Ponytail 与爆款插件、B 同类项目与学习证据、C 顶级导师语料、D 宿主能力与继承、E 现有知识盘点）。星数是 2026-10-15 用 `gh api` 测的，当天会漂几十星，正文取约数，精确值见附件。下面只写会影响设计的结论。

### 3.1 Ponytail 和这一批爆款插件，赢在哪

**Ponytail 的事实**（164k 星，2026-06-12 才创建；按 star-history 曲线估，第一周约 3.7 万）：

- **本体只有一页。** 核心是一个 52 行的 `SKILL.md`，人设是"像屋里最懒的资深工程师那样想"：只写最少的代码，但校验、安全不砍。其余约 2,400 行全是 hook 和适配器，用来把这一页送进约 30 个宿主。
- **轻。** 零 npm 依赖（PATH 里有 node 就行）；Claude Code 两条命令装完；6 个命令、3 档、零配置。
- **常驻注入才是生效的关键。** JetBrains 测过（原文打不开，两篇转述一致）：只装 skill、不装 hook，10 次会话自动触发 0 次。
- **机制不是它原创的。** 常驻注入、三档、退出词，caveman 4 月就有。它赢在人设、诚实和克制：有人在 #126 指出它的基准测试虚高，作者两天内重做并公开认错。JetBrains 独立复测的效果大约是宣传的 1/3（代码 −15%，成本 −10%）。
- **用户骂得最凶的三件事**：往用户代码里写品牌注释（#120，有人因此卸载）；人设句式传染到用户自己的文档（#737）；子 agent 也被一律注入，导致审稿子 agent 少报问题（#502）。
- **治理：改任何一条规则，都要先跑三组对照**（基线 / 当前 / 改动，每组至少 6 次）。

**另外 9 个高星插件（24k 到 299k 星）的共性**：一句话能讲清的人设；大多常驻注入（agent-skills 是例外，故意交给宿主原生路由）；首屏放带数字的前后对比；内容只有一份，适配层很薄；两步以内装完；维护者把关严。

**反面教材**：拿功能数量当卖点（SuperClaude 起步最早，星数最低）；重依赖、要登录（claude-mem 默认引导登录托管服务）；夸大数字；污染用户产物；迁仓（GSD 旧仓 64k 星，迁到新仓只剩 10k）。

**对我们意味着什么：**

1. **产品本体应该是一页导师规则**（60 行以内）。卡片按需加载；上游 skill 按名字调用，不常驻。
2. **规则要靠 hook 送进会话。** 只装 skill 基本不会被触发。但送进去以后，四个动作守不守得住，全靠主模型读规则；规则在长会话里会走样（#737 就是），要用评测和真实会话抽查盯着。
3. **绝不把导师的口吻、标记写进用户的论文和代码。** 这在学术写作里比在代码里更致命：文风被带偏，审稿人会看出来。
4. **方向和 Ponytail 相反。** 它要 agent 少写；学习需要人多想。更近的先例是官方 learning-output-style：在决策点留空，让人亲手写 5 到 10 行。
5. **规则当代码管，卡片开放贡献。** 改导师规则先过评测；README 里的数字要能被别人复现；永远不说"你学会了 X%"。Ponytail 基本不收外部 skill，我们要兼容 Supervisor-Skills 的社区署名，所以卡片内容开放贡献。

### 3.2 同类项目：在查到的范围内，没有人同时做到四件事

| 项目 | 星 | 人在里面是什么角色 | 有没有让人学到东西的机制 |
|---|---|---|---|
| karpathy/autoresearch | 98k | 只写一份 `program.md`，agent 通宵改代码、跑实验 | 无 |
| Imbad0202/academic-research-skills（下称 ARS） | 52k | 作者兼把关人，每阶段确认 | **有**：每个检查点一段"协作深度"观察；Socratic Mentor 在探索阶段提问；收尾出过程记录（关键决策、Key Lessons、1 到 100 分的协作评分） |
| K-Dense-AI/scientific-agent-skills | 50k | 委托人 | 无 |
| ARIS（wanshuiyin） | 17.5k | 在检查点审批 | 无 |
| HKUSTDial/Supervisor-Skills | 9.7k | 作者 | 无：skill 里没有复盘或学习环节 |
| Claude Code 官方 Learning 风格 | 官方内置 | 在有真实分歧的地方亲手写 5 到 10 行代码 | 有，但粒度是几行代码，没有复盘，也不跨会话 |
| 以"导师"为定位的科研插件（paper-tutor-skills、research-mentor、METIS 等） | 都不到 500 | 学习者 | 有，但多是上课式，或者干脆拒绝干活；都没做真人学习效果评估 |

ARS 是离我们最近、也最大的一家，必须说清区别。它在写作阶段同样摊开决策（过程记录里引用用户原话）、同样会提问，所以写引言这类场景不是我们的差异点。照"你怎么用的 AI"这件事本身也有证据支持（§3.3 的 Maier 实验），我们的复盘同样会照。站得住的差异有三条：
- 它给协作打 1 到 100 分，正是你否决过的等级制；
- 它明确不跑实验（"never runs experiments"），而实验恰恰是 vibe research 里最黑的一段；
- 据我们查到的材料，它没有"放手"：不会因为你说会了就不再管。

**空白**（推断）：在查到的范围内（B 线定向查了几十个项目，又按简介粗筛了一个榜单上 116 个百星以上的学术 skill），没有项目同时做到下面四件事：

1. 嵌在真实科研流程里，包括实验和代码；
2. 在研究决策这一级（选 baseline、设计消融、解读负结果、回审稿意见）把判断交还给人；
3. 在里程碑处复盘，不打分；
4. 你说"这类我会了"，它就跨会话记住，不再管。

### 3.3 证据：AI 怎么用才不伤学习

| 研究 | 做了什么 | 结论 | 对设计的意思 |
|---|---|---|---|
| Shen & Tamkin 2026（Anthropic，arXiv 2601.20245） | 52 名开发者学一个新的异步库，随机分成用 AI 和不用 AI，之后做不用 AI 的测验 | 用 AI 组测验 50%，手写组 67%，平均也没更快。按使用方式细分（每种只有 2 到 7 人，属探索性分析）：全权委托、让 AI 反复调试的人学得最差；生成后追问、只问概念的人学习没受损 | 伤学习的主要是把思考外包，不是用 AI 本身（初步证据） |
| Bastani et al. 2025（PNAS） | 近千名高中生，无护栏 GPT、只给提示的 GPT、无 AI 三组 | 无护栏组练习 +48%，撤掉 AI 后考试 −17%；只给提示组负效应基本消除，但没有增益；学生自己察觉不到 | 光靠限制只能止损；不能信"我觉得学会了" |
| Maier et al. 2026（arXiv 2609.20143，预注册，704 人） | 不限制 AI；每题之后告诉对方"你刚才怎么用的、因此少练了什么、下一题注意什么" | 外包答案减少（OR 0.47），测验成绩上升（OR 1.51）；按努力给奖励没有效果 | 事后照一下"你怎么用的 AI"有用，积分奖惩没用。注意：它照的是使用方式，不是研究内容；任务是分数运算，很窄 |
| 复盘元分析（Tannenbaum & Cerasoli 2013） | 46 个样本，2,136 人 | 复盘平均提升绩效约 25%（d=0.67）。这里的复盘是参与者自己回顾、一起讨论，不是发一份报告；美军 AAR 原则写明"不是批评，不打分" | 复盘要本人参与才算数 |
| 认知学徒制（Collins, Brown & Newman 1989） | 教育学经典框架 | 核心是双向可见：专家的思考让学生看见，学生的思考让老师看见 | 正好对应你说的"黑盒" |
| 刻意练习（Macnamara 2014 元分析） | 刻意练习对表现的解释力 | 在职业领域只解释不到 1% 的方差 | 别做刷题和练习册 |

B 线从这些材料里归纳出一个"会不会滑向上课"的判别式，我认为可以直接当产品规则：

> 下面四条同时满足才算"在工作里长本事"，破一条就开始像上课：(a) 对象是当前任务里的真实产物或决策；(b) 人的输入会改变结果；(c) 由工作里的事件触发，不按课程表；(d) 不显示分数或等级。

### 3.4 宿主能力与继承机制

**两个宿主已经趋同。** 本机 Claude Code 2.1.300 有 33 个 hook 事件，Codex 0.162.1 有 12 个，两边都有 SessionStart、UserPromptSubmit、PostToolUse、Stop、SessionEnd。Codex 给插件 hook 也设置了 `CLAUDE_PLUGIN_ROOT`，所以同一份 hooks.json 两边都能用。Ponytail 就是这么做的。

**四条硬约束，直接决定架构：**

1. hook 里不能让模型写正文：Claude Code 的 prompt/agent 型 hook 只能回 ok/reason，Codex 不支持这两类。所以**复盘只能由主模型在会话里写**。
2. 会话结束 hook 只给 1.5 秒（Claude Code 插件）/ 最多 3 秒（Codex）：只够写一个标记。
3. 单次注入有上限：Claude Code 1 万字符，Codex 约 2,500 token，超了只给预览。所以开会话时注入的内容要压在约 1,500 token 以内。
4. Codex 的摩擦：插件 hook 要用户在 `/hooks` 里点信任；带 hook 的插件进不了 Codex 公开插件目录；IDE 扩展不支持插件。

**继承署名：**

| 方案 | 上游作者会不会出现在 contributors | 代价 |
|---|---|---|
| `git subtree add`，不 squash | 会（Duck 实测） | 仓库里多一份上游历史；上游新作者要等 `subtree pull` 才出现 |
| fork | 会 | 带 fork 标签，默认搜不到；你在 fork 里的提交不计入个人贡献图 |
| fork 后在设置里 Leave fork network | 应该会（推断：git 历史全保留） | 只对公开、小于 1GB、没有下级 fork 的仓库开放；不可逆；fork 期间的星和 issue 不带走（[GitHub 文档](https://docs.github.com/en/pull-requests/how-tos/work-with-forks/detaching-a-fork)） |
| commit 里写 `Co-authored-by` | 不会（github.com 实测；官方文档里"计入共同作者"那句只出现在企业版页面） | 无 |
| README 致谢、.mailmap | 不会（.mailmap 为推断） | 无 |

**安装体积是真问题，有两条候选解法，都待实测。** 上游当前文件树约 52MB（handbook 30.5MB、skills 13.4MB、assets 8.5MB，大头是讲义 PDF 和图片）。本机的第三方插件市场是浅克隆，历史不拖累安装，但当前文件树会整个拉下来：本机 nature-skills 的市场目录就有 88MB。两条解法：

- **(a) 另开一个市场小仓库。** 里面只放 marketplace.json，插件来源用 `git-subdir`（Claude Code 市场条目的一种写法，只检出仓库里的一个子目录）指回本仓库的 `plugin/`。
- **(b) 在 vendor 里删大文件。** subtree 导入后，在自己的一个提交里删掉 vendor 里的 PDF 和图片。上游的提交仍在默认分支历史里，contributors 应当不受影响（推断）；当前树瘦到几 MB。代价是以后 `subtree pull` 碰到上游改这些文件时要手工处理。

Codex 安装时怎么克隆没查到，也要实测。

## 四、方案草图（供讨论，不是定稿）

### 4.1 一句话

> AI 照常干活；导师把每个研究决策摊开给你看，要你拍板的先问你，干完和你一起复盘。你说会了的，它就不再管。

它首先得让研究本身变好：在你被导师和审稿人问住之前，先把 baseline 太旧、seed 太少、论断说过头这些问题指出来。"你长了本事"是它和别的科研插件最不一样的地方；但如果它只讲学习、不帮你把活干好，就成了又一个学习模式，和 ChatGPT、Gemini 自带的那些没有区别。

### 4.2 学习循环：四个动作

| 动作 | 做什么 | 对应你要的 | 依据 |
|---|---|---|---|
| **摊开** | 有研究决策的那一轮（选数据、选 baseline、选指标、定 seed 数、解读结果、定论断范围），回复末尾加一行：决定了什么、为什么、否掉了什么、谁定的（你还是 AI）。同一行追加进 `.advisor/decisions.md`。没有研究决策的轮次，一个字不加。你想写一行预期，可以自己写进去，它不问 | 科研要点；黑盒变透明 | 认知学徒制的"示范"：把专家的思考外化 |
| **先问** | 要你拍板的决策，先问你，再执行。只问你的回答会改变计划的（比不比某个 baseline、seed 跑几个、论断说到多大）；不问考你知识的问题，也不问"你猜结果是多少"这种答了也不改变任何事的问题，你 7 月否决的"课前提问"就是这一类。每个任务（一次请求到交付）最多问一次；你说"你定"，就由 AI 定，记作 AI 的决定 | 让人自己动脑的那一下 | 生成效应；Anthropic 实验里生成后追问、只问概念的人学习没受损 |
| **复盘** | 里程碑处（实验跑完、一节写完、投稿、被拒、rebuttal 结束）你敲 `/debrief`（Codex 里是 `$debrief`）。先请你说一句：这次哪一步是你自己定的，哪一步最想重来；不想说可以跳过。导师再补五项：本来想干什么 / 实际怎样 / 顶级导师会盯哪里（带出处）/ 这次哪些判断交给了 AI（下次想自己来，回一句就行）/ 下一步。你的说法和决策记录并排放。不打分 | 学到了什么、技术栈、具体怎么做 | 复盘元分析（要本人参与）；Maier 实验的"照使用方式" |
| **放手** | 你说"这类我会了，别再问"，它记进一份清单，这一类以后不再问、不再讲。清单里只有你说过的话：没有对你的任何评价，模型也不自己推断你会不会 | 随你进步而变化，由你说了算 | 认知学徒制的"逐步撤除支架"。撤支架本来要靠准确诊断；不出题就没有可靠的诊断，所以把判断权交给你 |

写进 ADVISOR.md（那页导师规则）的硬规则，四个动作都要守：
1. 过 §3.3 的四条判别式；
2. 决策记录、复盘和清单里不出现任何对你的评价，也不做成长档案；
3. 导师的话只出现在对话和 `.advisor/` 里，绝不写进你的论文和代码（Ponytail #120、#737 的教训）；
4. 不往审稿类子 agent 里注入（#502）。

### 4.3 四个场景（请重点批注这里：哪里像上课，哪里不像你要的导师）

**场景一：跑对比实验。** 你说"帮我跑我的方法和 3 个 baseline 的对比，出个表"。

- 不装插件：agent 自己挑 baseline、自己定超参、跑一个 seed，出一张加粗的表。你不知道为什么是这 3 个，也不知道差距显不显著。组会上被问"为什么不比 X"，答不上来。
- 装了之后：
  - **先问**："候选里的 D 用了额外数据。比不比？比的话，表里要注明。"这个决定改变表里有几列、审稿人会不会追问，只有你能拍板。
  - **摊开**：回复末尾一行，"baseline 选 A/B/C：同数据、同算力、各用论文推荐的超参；D 按你的意思放进表、加脚注；seed 定 3 个（AI 定的）"，同时记进决策记录。
  - 结果出来时导师插一句："提升 0.8，seed 间标准差 1.2，按这个方差，审稿人会说不显著。"
  - **复盘**：你敲 `/debrief`，先说一句："D 是我定的；seed 太少，最想重来。"导师补：本来想证明比最强的 baseline 好；实际 +0.8 ± 1.2，不显著。顶级导师会盯两处：方差与显著性（NeurIPS 投稿清单第 7 项）、baseline 够不够新（`idea-evaluator` 的致命缺陷清单把超过 12 个月的 baseline 列为红旗）。这次交给 AI 的判断：seed 数、显著性检验的做法（配对 bootstrap）；下次想自己定 seed 数，回一句就行。下一步二选一：加到 5 个 seed，或把论断改成"可比"。你选。
  - **放手**：如果你回"显著性检验这块我会了，别讲了"，它记下，以后只做不讲。

**场景二：写引言。** 你说"帮我写 Introduction"。（这一幕 ARS 也会做类似的提问，不是我们的差异点；放进来是因为它最常见。）

- 不装：agent 直接交出一页漂亮的引言，贡献点是一串功能；你说不清这篇论文到底主张什么。
- 装了之后：
  - **先问**："用一句话说：读者读完应该相信什么？"你的答案决定整节往哪写；答不上来的话，真正的问题就在这里，比写引言更值得先解决（H1，7 个独立来源）。
  - **摊开**：按手册 3.2 的六段结构写，每段为什么这么组织，各一行。
  - 导师卡片："贡献要具体到可以被证伪；含糊、不可证伪或本来就该做的工作，都是弱贡献"（出处：`intro-drafter/references/contribution-patterns.md`）。
  - **复盘**：你先说这节最没把握的是哪段；导师补论证链"问题 → 缺口 → 方案 → 证据"在哪一环断了；贡献 2 在实验里还没有支撑，这是下一步。

**场景三：评估 idea。** 你说"我想做 X，帮我看看能不能做"。

- 不装：agent 给一份"很有前景"的报告。
- 装了之后：
  - **先问**："你觉得最可能让它死掉的是什么？"这一问不是考你：你知道 AI 不知道的领域约束，你的回答决定先查哪一条；先打掉最大的风险，正是 H3 说的"以最快速度降低不确定性"。
  - **摊开**：`idea-evaluator` 逐条过致命缺陷，每条判断写清理由。
  - **复盘**：你先说一句现在还想不想做；导师补这次用到了哪几条评估标准、各自的出处。

**场景四：不顺的时候。** deadline 前一天，你只想让它赶紧把实验补完。

- 你今天不想被打扰，敲 `/advisor quiet`：只往决策记录里写，不在对话里说话，一个问题也不问。
- 没开 quiet 时，它问"seed 跑几个"，你回"你定"：记成 AI 的决定，这个任务里不再问。
- 它问了一个你觉得多余的问题：你回"这类别问了"，记进清单，以后同类不再问。
- 跑完你直接关掉窗口：不拦你。下次在这个项目里开会话，它提一句"上次有 4 个研究决策还没复盘，想做就 `/debrief`"；你不理，它不再提。
- 在别的项目里（改服务器脚本、写邮件），它一个字都不说，因为你没在那里开过导师。

这一幕最想请你挑：哪里还是嫌烦。

### 4.4 架构：一页本体，两层按需，一层薄适配

```
仓库/
├─ plugin/                      用户实际安装的部分，目标 < 1MB
│  ├─ skills/advisor/SKILL.md   一页导师规则（≤60 行），产品本体，下文简称 ADVISOR.md
│  ├─ skills/debrief/SKILL.md   复盘
│  ├─ cards/                    导师卡片，按需注入（每张：原则 / 为什么 / 怎么做 / 常见错误 / 出处 / 适用范围）
│  ├─ hooks/hooks.json          Claude Code 与 Codex 共用
│  ├─ hooks/advisor.py          单文件，只用 Python 标准库；/advisor 开关也由它解析
│  ├─ .claude-plugin/  .codex-plugin/
│  └─ AGENTS.md                 没有插件系统的宿主用这个兜底
├─ vendor/supervisor-skills/    git subtree 导入，不 squash；只读；不随插件分发（D1 选 A 时才有）
├─ corpus/                      顶级导师来源清单与转述底稿（卡片的出处）
├─ evals/                       改导师规则之前必须过的对照评测
└─ LICENSE（代码 MIT） + LICENSES/（内容 CC BY-NC-SA 4.0，按目录写清）
```

- **上游 skill 不在插件里放拷贝。** 场景要用的内容（比如 `idea-evaluator` 里"baseline 超过 12 个月是红旗"）提炼成卡片随插件走，不依赖上游装没装；装了 Supervisor-Skills 的，ADVISOR.md 会在合适的时候调用它们（写引言时用 `intro-drafter`）。不放拷贝，是因为插件里每个 skill 的描述在每个会话都占上下文（本地 11 个 skill 的描述合计约 770 个英文词，上游 9 月又加了 1 个，折合一千 token 上下）：内置就等于替每个装导师的人默认付这笔，已经装了上游的人还要付两份、两套同名 skill 抢调用；也免得维护第二份拷贝。**代价**：想用全部 skill 的人要另装 Supervisor-Skills，D1 选 A 时就是两次安装。发布前的解法：把 Supervisor-Skills 本身做成插件，在我们的 plugin.json 里声明为依赖（Claude Code 支持，Codex 没查到），一次装完，这需要上游配合；或者 D1 选 B。MVP 先接受两次安装，`/advisor on` 时检测上游装没装，没装就提示一句。
- **只在你开启过的项目里说话。** 你敲 `/advisor on`，hook 脚本直接在项目里建 `.advisor/`，不经过模型；没有这个目录的项目，hook 直接退出，一个字不注入。

| 事件 | 干什么 | 预算 | MVP |
|---|---|---|---|
| SessionStart | 注入 ADVISOR.md 和"别再问"清单；有还没复盘的决策、且这一批没提醒过时，附一句提醒，提醒后记标记，不再附 | ≤ 1,500 token | 做 |
| UserPromptSubmit | 解析 `/advisor on\|quiet\|off`；按关键词判断你在哪个科研阶段，注入最多 2 张相关卡片的摘要（MVP 的关键词只覆盖场景一） | 命中才注入，≤ 600 token | 做 |
| PostToolUse | 记事件，识别里程碑（实验跑完、PDF 编译完） | 不注入 | 发布前看真实会话再定：脚本分不清冒烟测试和正式实验 |
| SessionEnd | 写"待复盘"标记 | < 1.5 秒 | 发布前再定 |
| Stop | 有里程碑没复盘时拦一次 | | 不做：拦人收工就是门禁，Duck 的老路 |

- **hook 只管送内容和记状态。** 四个动作守不守得住，靠主模型读规则；用 `evals/` 测改动前后的回归，用真实会话抽查运行时有没有走样。
- **入口两个，都是 skill**：`/debrief`（复盘）和 `/advisor on|quiet|off`（开关和档位）。advisor 这个 skill 就是那页导师规则；你敲 `/advisor on` 时，UserPromptSubmit hook 看到这一句，直接切开关、建 `.advisor/`。Ponytail 的 `/ponytail lite|full|ultra|off` 就是这么做的：skill 本体加 hook 解析。Codex 里对应 `$debrief`、`$advisor on`。代价是这两个 skill 的描述每个会话都在，目标合计一百 token 以内。
- **数据全在本地**：项目里 `.advisor/decisions.md`（决策记录，顺便可以当 AI 使用披露的底稿）和 `.advisor/debriefs/`；"别再问"清单 `~/.advisor/skip.md`。不上传，不要账号，不做遥测。
- **依赖**：
  - 你机器上需要的：Python 3（只用标准库）。缺了也不报错：hook 静默失效，导师规则不注入，别的照常。
  - 只有维护者用的（用户不需要）：转述重叠检查、对照评测（要调模型、花钱）、存档链接、上游段落哈希。
- **更多宿主**：没有插件系统的宿主用 AGENTS.md 兜底；以后要铺开，skill 那一层可以学 agent-skills，借 skills CLI 一次覆盖 70 多个宿主（附件 A）。MVP 不做。

### 4.5 MVP：做什么、不做什么、怎么验收

**MVP：几天内跑通场景一**
- ADVISOR.md（≤60 行）、`/debrief`、`/advisor on|quiet|off`；
- 2 个 hook：SessionStart、UserPromptSubmit；
- 6 到 8 张卡片，只够场景一用：baseline 怎么选、对比公不公平、seed 和方差、显著性检验、论断说到多大；
- 先在 Claude Code 上跑通，同一份 hook 配置紧接着上 Codex；
- 开工前先把本地 Supervisor-Skills 同步到上游最新（落后 5 个提交，含 9 月的 `rebuttal-guidance`）；
- 验收：在你一个真实的实验任务上跑一次，看决策记录和复盘是不是你要的导师。

**发布前**
- 按 D1 落继承（subtree 是一条命令，什么时候做都不影响署名结果）；体积方案实测；
- 卡片扩到写作、选题、组会报告（约 40 张，每张走出处和转述规范）；
- README 首屏放 3 个真实任务的收据（一次实验、一节写作、一次 idea 评估）：前后对比加复盘截图；每轮注入多少 token 如实写；
- `evals/` 对照评测：改导师规则前后各跑几组；
- 维护者自测（不进产品）：借 Shen & Tamkin 的设计，两个相似任务交叉，一个装一个不装，事后问几个"这次为什么这么做"，只当演示，不当论文结论；
- PostToolUse、SessionEnd 要不要加，看真实会话再定。

**不做**：
- 门禁、证据文件、拦人收工、LaTeX 工具链（Duck 那一套）；
- 分数、等级、测验、学习计划、成长档案；
- 云端、账号、遥测；
- Cursor、Gemini 等宿主（只给 AGENTS.md 兜底）。

**节奏**：先用几天搭出能跑通场景一的最小骨架，在真实任务里看效果再定细节。不写 19 项任务的大计划。

### 4.6 最大的风险

| 风险 | 怎么防 |
|---|---|
| 只讲学习，没人装 | 第一卖点放研究质量（在导师和审稿人之前挑出问题）；学习是差异点 |
| 问多了被卸载 | 只问会改变计划的；每个任务最多一次；"你定"永远可以；"这类别问了"立刻生效；`quiet` 档 |
| 关键词误判，多塞卡片 | MVP 的关键词表只覆盖场景一；hook 在本地只记命中了哪个关键词（不记原话），发布前用真实会话调表 |
| 导师口吻污染论文文风 | 硬规则：导师的话不进用户文件 |
| 规则在长会话里走样 | 每次开会话重新注入；命中卡片时随卡片带一行规则提醒；真实会话抽查 |
| "顶级标准"被人挑出处 | 每张卡片带出处和适用范围；有分歧的写明是哪家的看法 |
| 手册与卡片两份知识漂移 | 卡片记录来源路径和段落哈希，上游一改就标出受影响的卡片 |
| Codex 侧摩擦 | 安装说明里写清 `/hooks` 信任一步；不依赖进 Codex 公开目录 |

### 怎么讨论

Duck 的历史里，你两次扭转方向（"变成了上课，不是科研中的流程"；"我们和作者一起写论文，你不能忘记这个事情"），都是看到具体场景时才发生的，读抽象 spec 时没有。所以我建议这样讨论：

1. **这一轮，你批注，大约半小时**：在 §4.3 四个场景上批注哪里像上课、哪里不像你要的导师，尤其场景四；§5 的决策逐条回"同意"或"改成 X"。
2. **下一轮，我出东西**：2 页 spec 加仓库骨架（`plugin/` 目录、一页导师规则、2 个 hook、6 到 8 张卡片），把场景一端到端跑通。
3. **再下一轮，一起看收据**：在你一个真实任务上跑一次，对着真实输出改规则。
