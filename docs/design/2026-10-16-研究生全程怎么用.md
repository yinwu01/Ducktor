# 一个研究生从头到尾怎么用这个插件（2026-10-16）

> 这是示意稿：插件还没写，下面的命令、对话和报告都是按设计画出来的样子。命令已经按 10-16 定下的方案改成 `/duck-` 开头（见《Doctor Duck：拆黑盒、命令、热插拔》讨论稿 §3）。以 Claude Code 为例；Codex 里用 `$` 叫技能，走插件安装时还要带插件名，比如 `$duck:duck-why`。

## 〇 一句话

插件做两件事，底下还有一层常驻部分：

1. **用斜杠叫导师干活。** 原来 Supervisor-Skills 的 11 个技能全部变成插件命令：查文献、评估 idea、理论文逻辑、写作、润色、画图、投稿前审稿。敲 `/duck-` 加一个词就能叫出对应的技能，比如 `/duck-idea`；记不住就敲 `/duck` 再说一句话，它替你挑一个，并先告诉你挑了哪个。不敲斜杠、直接说"帮我评估这个 idea"时，第一版只建议你用哪个命令，不自己跑。
2. **每次干完附一份「为什么」。** 它替你写了、搜了、评了东西之后，会在结尾附一份短报告，像导师一样讲清这么做的道理，以及你能带走的一条经验。这些经验记进项目里的笔记本，下次做同类任务时它会翻出来接着讲。这样转起来，就是知识闭环。
3. **常驻部分。** 你不敲命令、照常让 AI 干活时，它也在：要你拍板的事先问你，每条回复末尾记一行研究决策，做法撞上标准时插一句。报告负责讲清 why，可长本事还得靠你自己拍板：调研里复盘那项证据（Tannenbaum & Cerasoli 2013）说的是自己回顾、一起讨论，不是收一份报告。所以这一层保留。

## 一 全程总表

| 阶段 | 你敲什么 | 背后的技能 | 交回给你的 | 「为什么」讲什么 |
| --- | --- | --- | --- | --- |
| 摸方向 | `/duck-survey 帮我摸一下长文本推理加速的研究现状` | deep-research | 引用都核验过的综述报告 | 为什么这样分类；怎么看出一个方向还有空位 |
| 评估 idea | `/duck-idea 评估一下这个 idea：……` | idea-evaluator | 审稿人口吻的结论、致命问题检查 | 你的 idea 在五个维度里占了哪一维、哪一维在倒退；审稿人为什么先看这个 |
| 理论文逻辑 | `/duck-outline 帮我把这篇的逻辑理一遍` | tech-paper-template、benchmark-paper-template | 思考模板表、自洽检查 | 为什么每个方法模块都要对上一个挑战 |
| 做实验 | 照常让 AI 写代码、跑实验，不用敲命令；想问分工就敲 `/duck-vibe 这块该让 AI 干到哪` | 常驻部分，加上 vibe-research-workflow | 每条回复末尾一行决策记录；撞上标准时插一句 | 为什么这个 baseline 不能少；为什么至少跑 3 个 seed |
| 写作 | `/duck-intro 写 Introduction，材料在 notes/ 和 results/`；别的章节用 `/duck-write` | intro-drafter、paper-writer | 正文 | 六段各管什么；你之前记下的哪条经验在这里用上了 |
| 润色 | `/duck-polish 润色这段` | paper-polish | 改好的段落 | 每一类改动背后的规则，比如语气要和证据强度相称 |
| 投稿前 | `/duck-review 投稿前帮我审一遍` | pre-submission-reviewer | 按 CRITICAL / MAJOR / MINOR 分级的问题清单 | 审稿人为什么会抓这几条 |
| 阶段收尾 | `/duck-learn` | 复盘 | 这一段的复盘 | 把这一段攒下的经验串起来 |

另外随时可以敲 `/duck-why`：对刚才 AI 做的任何一件事要一份「为什么」，没走插件技能的事也行。

目前没有专门技能的两块：做实验靠常驻部分兜着；rebuttal 不在继承的这批技能里，要自己补。

## 二 跟着一个学生走一遍（示意）

小周是一年级博士生，第一次独立做顶会论文，方向是长文本推理加速。插件装好以后，在项目目录里开会话就能用。第一次用时，它会在项目里建一个 `.duck/` 文件夹，放报告和笔记本。

### 第 1 周：摸方向

```
小周：/duck-survey 帮我摸一下长文本推理加速的研究现状，重点看跳过注意力计算这条线

鸭子：先定两件事，会改变搜索范围：
      1. 只看近两年，还是把早期的稀疏注意力也带上？
      2. 只看方法，还是也看系统实现（kernel、显存）？
小周：近两年，只看方法。

鸭子：（deep-research 的报告，节选）
      研究问题 3 个，从 5 个角度检索，核验引用 41 条，删掉 6 条找不到原文的。
      分类：按"在哪一步省计算"分成三类……
      空位：三类都只在单一长度上评测，没人系统比较不同上下文长度下的收益。

      ── 为什么 ─────────────────────────────
      做了什么：先把研究问题定死，再从 5 个角度检索，每条引用都核对了原文。
      为什么按"在哪一步省"来分：按方法名分，只看得出谁和谁像；按省在哪一步分，
        才看得出哪一步还没人做，空位就是这么找出来的。
      你能带走的一条：读一个方向，先找一根能把方法分开的轴，再看轴上哪里是空的。
      下次自己先做：动手搜之前，先写下 3 个具体的研究问题。
```

### 第 2 周：评估 idea

```
小周：/duck-idea 评估一下这个 idea：用一个小模型先判断哪些 token 可以跳过
      注意力计算，长文本推理能省 40% 时间

鸭子：先确认两件事，你的回答会改变结论：
      1. 40% 是实测的，还是估算的？
      2. 准确率最多掉多少你能接受？
小周：估算的。掉 1 个点以内吧。

鸭子：（idea-evaluator 的结论，节选）
      值得做，待验证。
      - 五个维度里你只占"更快"，而"更高"还在倒退：准确率要掉。审稿人会问：
        为什么不用现有的 token 剪枝方法？
      - "更快"这一维现在只能标成"按机制推断，还没有数据证实"。
        第一件事：在一个公开 benchmark 上把这 40% 实测出来。

      ── 为什么 ─────────────────────────────
      做了什么：用五个维度给 idea 定位，查了致命问题。
      为什么先看维度：审稿人先问的是"比已有工作强在哪一维"。只占一维、
        另一维还在倒退，很容易被归成增量工作。（idea-evaluator 的维度说明）
      你能带走的一条：至少在一维上明显领先；倒退的那一维，要么修好，
        要么在论文里正面讲清代价。
      下次自己先做：动手前用一句话写出"我们比 X 快在哪、代价是什么"。
      已记进 .duck/notebook.md
```

### 第 4 到 6 周：做实验

这段时间小周照常让 AI 写代码、跑实验，不敲命令。常驻部分在后台起作用：

```
小周：结果出来了，我们 81.3，最强的剪枝 baseline 80.5（不加速的原模型 81.9），写进表吧

鸭子：先说一句：现在只跑了 1 个 seed，0.8 的差距可能就是随机波动。
      建议补到 3 个 seed，再报均值和标准差。要补吗？
小周：补。
...
▸ 决策：seed 1→3（你定）；表里报均值±标准差（AI 定）
```

这里不出完整报告，只插一句、记一行决策，命中的这条标准也记进笔记本。为什么至少要 3 个 seed，留到 `/duck-learn` 里讲。

### 第 7 周：写引言，闭环在这里接上

```
小周：/duck-intro 写 Introduction，材料在 notes/ 和 results/

鸭子：（intro-drafter 写好的六段引言）

      ── 为什么 ─────────────────────────────
      做了什么：按六段逻辑写了引言：背景和贯穿全文的例子、现有方法的局限、
        问题本质和目标、关键挑战、方法概览、贡献。
      为什么方法概览里要交代准确率的代价：这是你第 2 周记下的那条经验，
        "倒退的那一维要正面讲清代价"（笔记本第 2 条）。审稿人自己发现代价，
        和你主动讲清楚，印象完全不同。
      你能带走的一条：第五段的每个方法模块，都要对上第四段的一个挑战；
        贡献则各落到一个章节。（手册第 3 章）
      下次自己先做：写方法概览前，先把挑战列出来，一条对一条。
```

### 第 8 周：投稿前

```
小周：/duck-review 投稿前帮我审一遍

鸭子：（pre-submission-reviewer 的清单）
      CRITICAL 1 条：表 2 的 baseline 设置和正文描述不一致。
      MAJOR 3 条……

      ── 为什么（节选）───────────────────────
      为什么这条是 CRITICAL：数字对不上，审稿人会怀疑整篇的实验，
        别的优点都救不回来。
      你能带走的一条：改实验设置时，正文、表格、附录三处一起改。
```

### 投稿以后：`/duck-learn`

```
小周：/duck-learn

鸭子：先说一句：这次哪一步是你自己定的，哪一步最想重来？不想说可以跳过。
小周：idea 和补 seed 是我定的。最想重来的是摸方向，搜得太窄了。

鸭子：本来想干什么：证明跳过注意力计算能在长文本上省 40% 时间。
      实际怎样：实测省 31%；准确率比原模型低 0.6 个点，比最强的剪枝 baseline 高。
      顶级导师会盯哪里：第 5 周那次，0.8 的差距只有 1 个 seed 撑着。差距没超出
        seed 之间的波动，就说明不了方法更好，所以至少跑 3 个 seed，报均值和
        标准差。（NeurIPS 投稿清单第 7 项）
      这次交给 AI 的判断：表里报均值±标准差。下次想自己定，说一声就行。
      下一步：你说摸方向搜窄了，下一篇开题时先多加两个检索角度。
```

你开头说的那句会直接影响"下一步"写什么；不想说，就只看导师那五项。

### 不想听的时候

- 说"这类我懂了，别讲了"：这一类以后只记进笔记本，不再在对话里讲。
- 敲 `/duck quiet`：整段时间都不出报告，只记录。

## 三 「为什么」报告的固定格式

- **四段**：做了什么；为什么这么做，带出处（手册章节、技能里的说明、导师原话、投稿清单这类公开规范，或者你笔记本里的旧条目）；你能带走的一条；下次自己先做什么。
- **长度**：对话里 5 到 8 行；完整版存到 `.duck/reports/日期-任务.md`。
- **什么时候出**：插件技能每跑完一次出一份；随时敲 `/duck-why` 也能要。常驻部分撞上标准时只插一句、记一行，完整的讲解留到 `/duck-learn`。闲聊、改错别字这类小事不出。
- **不做的事**（7 月就定下的）：不出题、不布置作业、不给人打分、不写成长档案。笔记本只记原则，不评价人。技能给 idea 或稿子打分照旧，那是评东西，不是评人。

## 四 知识闭环怎么转

1. **记**：每份报告里"你能带走的一条"，加上常驻部分插话时命中的那条标准，追加到 `.duck/notebook.md`，一行一条，带日期和出处。小周这一轮记下的是：
   ```
   - 03-02 摸方向｜先找一根能把方法分开的轴，再看轴上哪里是空的（deep-research 报告）
   - 03-09 评估 idea｜至少一维明显领先；倒退的维度要么修好，要么正面讲代价（idea-evaluator 维度说明）
   - 03-30 做实验｜差距没超出 seed 间的波动，就不能写"优于"（NeurIPS 投稿清单第 7 项）
   - 04-13 写引言｜每个方法模块对上一个挑战，贡献各落到一个章节（手册第 3 章）
   - 04-20 投稿前｜改实验设置时，正文、表格、附录三处一起改
   ```
2. **用**：下次做同类任务前，它先翻笔记本；相关的旧条目会出现在新报告的"为什么"里，就像第 7 周那样。
3. **收**：你说懂了的那一类，以后只记不讲。
4. **串**：`/duck-learn` 在阶段结尾，把这一段的条目连起来讲。

## 五 和之前讨论稿不一样的地方

- **11 个技能全部打进插件。** 讨论稿里我建议不打包，为的是每个会话省下约 1k token 的技能描述；这点成本可以接受，按你的要求改。
- **「为什么」报告当主角。** 原来只在复盘里出现，现在每次实质性任务结束都有。常驻部分保留，原因见〇的第 3 条。
- **MVP 分两步（我的建议）。** 第一步：11 个技能接进插件，加上「为什么」报告、笔记本、每条回复末尾的决策行，以及"这类别讲了"。四个动作都在里面：先问、摊开、复盘、放手。第二步：跑实验时按标准插话。
