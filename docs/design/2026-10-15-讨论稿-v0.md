# 导师插件：理解、复盘、调研与讨论稿

2026-10-15 · 讨论稿 v0 · 只调研和提方案，没有写任何代码，也没有删任何东西

## 〇、一页结论

**你要做的**：研究生用 AI agent 做科研时，往过程里嵌一位导师。AI 照常干活；导师让过程不再是黑盒，在关键处按顶级标准把关，让人在真实工作里长本事。

**Professor Goose / Duck**：它后来改名叫 Professor Duck，是 GitHub 私有仓，0 星，7 月 20 日起冻结。我同意它不行。问题不在代码，在方向和重量：
- 它管的是 agent，没管人；
- 旗舰放在 LaTeX 排版上；
- 10 个命令、3 个系统依赖、只支持 Claude Code、仓库 36MB。

值得带走的是几条结论，不是代码。删之前要先补一个备份：现有的 bundle 不包含当前 HEAD。

**调研里最影响设计的五条**：

1. **Ponytail（164k 星）的本体只是一页 52 行的提示词。** 它能生效，靠的是 hook 在每次会话开始时自动注入。只装 skill、不装 hook 的话，10 次会话一次都没触发。它赢在人设、诚实和克制，机制本身不是原创。所以我们的本体也应该是一页导师规则。
2. **这个空白是真的。** 下面四件事，没有项目同时做到：
   - 嵌在包括实验的真实科研流程里；
   - 在研究决策这一级把判断交还给人；
   - 在里程碑处复盘，但不打分；
   - 跨会话记住人会了什么，会了的就不再管。

   最接近的是 academic-research-skills（52k 星），但它给人打分，评的是"你怎么用 AI"，而且不跑实验。
3. **证据（都已核实）。** 只读复盘学不到多少东西。伤学习的是把思考外包出去，不是用 AI 本身。事后照一下镜子有用（704 人预注册实验）；积分奖惩没用。所以学习循环里必须有一下"人先想"，但不能有分数。
4. **技术上轻量可行。**
   - Claude Code 和 Codex 可以共用一份 hook 配置。
   - 复盘只能由主模型在会话里写。
   - 继承署名只有 subtree 有效，`Co-authored-by` 不算数。
   - 体积问题可以用"只分发子目录"绕开。
5. **顶级导师语料核实了 49 条。** 其中 8 条共识可以当硬标准，正好补上手册的几个空白：实验统计、局限性、组会报告、读博元技能。大部分来源只能转述加链接；NC 条款要提前想清楚。

**方案**：
- 一页导师规则，常驻注入。
- 四个动作：
  - **摊开**：每个研究决策写一行，说清为什么；
  - **先问**：每个任务最多问一次；
  - **复盘**：在里程碑处做，不打分；
  - **放手**：会了的不再管。
- Supervisor-Skills 的 skill 和导师卡片都按需加载。
- 5 个确定性 hook，2 个命令，零第三方依赖，Claude Code 和 Codex 同时支持。

**要你现在定的四件事**：
- D1 仓库放哪；
- D2 挂在谁名下；
- D3 要不要给商业化留口子（这决定能不能直接改编手册）；
- D4 学习循环的强度。

**怎么讨论**：
1. 你在 §4.3 的三个场景上批注，并回复 D1–D4；
2. 我出 2 页 spec 和仓库骨架，把一个场景跑通；
3. 在你的一个真实任务上跑一次，对着真实输出改。

## 一、我对你想法的理解

### 1.1 一句话

研究生用 AI agent 做科研时，往这个过程里嵌一位导师：AI 照常干活，导师让过程不再是黑盒，在关键处按顶级标准把关，并让人在真实工作里长本事。

### 1.2 你的四条架构要求，我的理解

| 你说的 | 我理解的具体含义 |
|---|---|
| 1. 足够轻量，容易适配 | 内核是文本（导师规则 + 经验卡片 + 现有 skill），钩子只负责"在对的时候把对的内容塞进上下文"，不做门禁；零第三方依赖；Claude Code 和 Codex 都能装 |
| 2. 最顶级标准的专业指导，收集哈佛、MIT 等导师的经验 | 导师说的每一条都有出处：Supervisor-Skills 手册 + 顶级导师公开的经验文章。多位导师共同强调的当硬标准，有分歧的标明是哪家的看法 |
| 3. 结合现有全部 skill | 不重写 skill。skill 负责"干活"，导师层套在外面负责"解释、提问、复盘" |
| 4. 继承关系（新仓库的 contributors 里显示原作者） | 两层继承：git 层导入上游历史保留署名；内容层原样引用上游 skill，上游改进能直接流进来 |

### 1.3 三处我想先挑明的张力

1. **"告诉你学到了什么"本身不产生学习。** 只读一份复盘，人会觉得懂了，其实没长本事（证据见 §3.3）。学习需要人在关键处自己动脑。可你 7 月明确否决过"上课"（出题、测验、学习模式、成长等级）。两者要同时成立，就只能让人动脑的那一下恰好是做研究本来就该做的事。§4 给了一个具体判据。
2. **新开仓库，还是在 Supervisor-Skills 里长出来。** 新仓库有独立品牌，但从 0 star 起步；而且按 Duck 的 subtree 做法，会把上游当前约 52MB 的文件（大头是一个 16.6MB 的讲义 PDF 和一批图片）放进仓库。插件安装虽然是浅克隆，但还是要拉下整个当前文件树，和"轻量"冲突。§3.4 有解法。
3. **"顶级标准"和骆老师手册的个人风格冲突时听谁。** 收进哈佛、MIT 导师的经验以后，必然有和手册不一致的地方，需要一条明确的裁决规则。

### 2.2 为什么你觉得烂：我的诊断

我同意"烂"。问题不在代码质量（测试用真产物，边界写得诚实），在方向和重量。

1. **重心放错了：管 agent，不育人。** 7 月 4 日 v1 spec 写的差异化定位是"别的工具优化产出，Professor Goose 同时优化使用它的人"。建完以后，README 开头介绍的是"给 LaTeX 论文项目用的 Claude Code 插件……用 hooks 检查写作、排版、审稿、配图这些任务有没有走完约定的收尾步骤"。导师复盘沦为门禁的一项义务：门禁只核验 `.duck/reports/` 下有没有一个大于 200 字节的 HTML。工程量几乎全花在防 agent 偷懒上。
2. **旗舰选在了最不需要导师的地方。** 旗舰是 LaTeX 排版（编译、渲染、逐页看三轮）。排版是体力活；研究生在 vibe research 里最缺的是判断（选题、实验设计、结论能说到多大），这些 Duck 基本没碰。
3. **太重。** 10 个命令；合同、证据 JSON、时间戳、逃生舱一整套概念；3 个系统依赖；只跑在 Claude Code；装一次拉 36MB。和"轻量、易适配"正好相反。
4. **门禁兑现不了承诺，只好写长免责。** 审计 F7：门禁和被门禁的 agent 在同一台机器、同一个信任域，证据文件和时间戳都能伪造。于是 README 首屏是一大段"先说清边界"，读起来是防守姿态。
5. **先造后看。** 第一次真实跑一单（07-18 的收据）是在开工两周之后。定位辩论打了 6 轮，前后用过 4 个名字。用户体验是最后才见到的东西。
6. **导师的知识很薄。** 专业内容基本只有手册里排版、作图、审稿的清单，没有你这次说的"顶级导师经验"这一层。

## 三、调研

五路并行调研，原始报告在同级目录 `2026-10-15-调研附件/`（A Ponytail 与爆款插件、B 同类项目与学习证据、C 顶级导师语料、D 宿主能力与继承、E 现有知识盘点）。星数都是 2026-10-15 用 `gh api` 实测的。下面只写会影响设计的结论。

### 3.1 Ponytail 和这一批爆款插件，赢在哪

**Ponytail 的事实**（164,025★，2026-06-12 才创建，第一周 3.7 万）：

- **本体只有一页。** 核心是一个 52 行的 `SKILL.md`，人设是"像屋里最懒的资深工程师那样想"：只写最少的代码，但校验、安全不砍。其余约 2,400 行全是 hook 和适配器，用来把这一页送进约 30 个宿主。
- **轻。** 零 npm 依赖（PATH 里有 node 就行）；Claude Code 两条命令装完；6 个命令、3 档、零配置。
- **常驻注入才是生效的关键。** JetBrains 实测：只装 skill、不装 hook 时，10 次会话自动触发 0 次。
- **机制不是它原创的。** 常驻注入、三档、退出词，caveman 4 月就有。它赢在人设、诚实和克制：有人在 #126 指出它的基准测试虚高，作者两天内重做并公开认错。JetBrains 独立复测的效果大约是宣传的 1/3（代码 −15%，成本 −10%）。
- **用户骂得最凶的三件事：**
  - 往用户代码里写品牌注释（#120，有人因此卸载）；
  - 人设句式传染到用户自己的文档（#737）；
  - 子 agent 也被一律注入，导致审稿子 agent 少报问题（#502）。
- **治理：改任何一条规则，都要先跑三组对照**（基线 / 当前 / 改动，每组至少 6 次）。

**8 个 10 万星级插件的共性**：一句话能讲清的人设；常驻注入；首屏放带数字的前后对比；内容只有一份，适配层很薄；两步以内装完；维护者把关严。

**反面教材**：
- 拿功能数量当卖点：SuperClaude 起步最早，星数最低。
- 重依赖、要登录：claude-mem 默认引导登录托管服务。
- 夸大数字。
- 污染用户产物。
- 迁仓：GSD 旧仓 6.4 万星，迁到新仓只剩 1 万。

**对我们意味着什么：**

1. **产品本体应该是一页"导师规则"**（60 行以内）。Supervisor-Skills 的 12 个 skill 和导师卡片都按需加载，不常驻。
2. **学习循环必须由 hook 驱动。** 只装 skill 基本不会被触发。
3. **人设要一个人人见过的原型。** 候选："组会上会问你'baseline 呢？对照组呢？'的那位导师"。
4. **绝不把导师的口吻、标记写进用户的论文和代码。** 这在学术写作里比在代码里更致命：文风被带偏，审稿人会看出来。
5. **规则当代码管。** 改导师规则先过评测；README 里的数字要能被别人复现；永远不说"你学会了 X%"。
6. **方向和 Ponytail 相反。** 它要 agent 少写；学习需要人多想。更近的先例是官方 learning-output-style：在决策点留空，让人亲手写 5–10 行。
7. **治理和 Ponytail 不同。** 它基本不收外部 skill；我们要兼容 Supervisor-Skills 的社区署名，所以卡片内容开放贡献，规则改动先过评测。

### 3.2 同类项目：没有人同时做到四件事

| 项目 | ★ | 人在里面是什么角色 | 有没有让人学到东西的机制 |
|---|---|---|---|
| karpathy/autoresearch | 97,947 | 只写一份 `program.md`，agent 通宵改代码、跑实验 | 无 |
| Imbad0202/academic-research-skills（下称 ARS） | 52,138 | 作者兼把关人，每阶段确认 | **有**：每个检查点一段"协作深度"观察；收尾出过程记录（关键决策、Key Lessons、1–100 分协作评分） |
| K-Dense-AI/scientific-agent-skills | 49,988 | 委托人 | 无 |
| ARIS（wanshuiyin） | 17,519 | 在检查点审批 | 无 |
| HKUSTDial/Supervisor-Skills | 9,691 | 作者 | 无：skill 里没有复盘或学习环节 |
| Claude Code 官方 Learning 风格 | 官方内置 | 在有真实分歧的地方亲手写 5–10 行代码 | 有，但粒度是几行代码，没有复盘，也不跨会话 |
| 以"导师"为定位的科研插件（paper-tutor-skills、research-mentor、METIS 等） | 都不到 500 | 学习者 | 有，但多是上课式，或者干脆拒绝干活；都没做真人学习效果评估 |

ARS 是离我们最近、也最大的一家，必须说清区别：它评的是"你怎么用 AI"，不是"你在课题里会了什么"；它打分、分 Zone，正是你否决过的等级制；它明确不跑实验，而实验恰恰是 vibe research 里最黑的一段；它不把 agent 自己做的研究决策摊开给人看。

**空白**：同时做到下面四件事的项目没查到。

1. 嵌在真实科研流程里，包括实验和代码；
2. 在研究决策这一级（选 baseline、设计消融、解读负结果、回审稿意见）把判断交还给人；
3. 在里程碑处复盘，不打分；
4. 跨会话记住人会了什么，会了的就不再管。

### 3.3 证据：AI 怎么用才不伤学习

| 研究 | 做了什么 | 结论 | 对设计的意思 |
|---|---|---|---|
| Shen & Tamkin 2026（Anthropic，arXiv 2601.20245，已核） | 52 名开发者学一个新的异步库，随机分成用 AI 和不用 AI，之后做不用 AI 的测验 | 用 AI 组测验 50%，手写组 67%，平均也没更快。全权委托、让 AI 反复调试的人学得最差；生成后追问、只问概念的人学习没受损 | 伤学习的是把思考外包，不是用 AI 本身 |
| Bastani et al. 2025（PNAS） | 近千名高中生，无护栏 GPT、只给提示的 GPT、无 AI 三组 | 无护栏组练习 +48%，撤掉 AI 后考试 −17%；只给提示组负效应基本消除，但没有增益；学生自己察觉不到 | 光靠限制只能止损；不能信"我觉得学会了" |
| Maier et al. 2026（arXiv 2609.20143，预注册，704 人，已核） | 不限制 AI；每题之后告诉对方"你刚才怎么用的、因此少练了什么、下一题注意什么" | 外包答案减少（OR 0.47），测验成绩上升（OR 1.51）；按努力给奖励没有效果 | 事后照一下镜子有用，积分奖惩没用。局限：任务是分数运算，很窄 |
| 复盘元分析（Tannenbaum & Cerasoli 2013） | 46 个样本，2,136 人 | 复盘平均提升绩效约 25%（d=0.67）。美军 AAR 原则写明"不是批评，不打分" | 里程碑复盘是证据最硬的一环 |
| 认知学徒制（Collins, Brown & Newman 1989） | 教育学经典框架 | 核心是双向可见：专家的思考让学生看见，学生的思考让老师看见 | 正好对应你说的"黑盒" |
| 刻意练习（Macnamara 2014 元分析） | 刻意练习对表现的解释力 | 在职业领域只解释不到 1% 的方差 | 别做刷题和练习册 |

B 线从这些材料里归纳出一个"会不会滑向上课"的判别式，我认为可以直接当产品规则：

> 下面四条同时满足才算"在工作里长本事"，破一条就开始像上课：(a) 对象是当前任务里的真实产物或决策；(b) 人的输入会改变结果；(c) 由工作里的事件触发，不按课程表；(d) 不显示分数或等级。

### 3.4 宿主能力与继承机制

**两个宿主已经趋同。** 本机 Claude Code 2.1.300 有 33 个 hook 事件，Codex 0.162.1 有 12 个，两边都有 SessionStart、UserPromptSubmit、PostToolUse、Stop、SessionEnd。Codex 给插件 hook 也设置了 `CLAUDE_PLUGIN_ROOT`，所以同一份 hooks.json 两边都能用。Ponytail 就是这么做的。

**四条硬约束，直接决定架构：**

1. hook 里不能让 LLM 写正文：Claude Code 的 prompt/agent 型 hook 只能回 ok/reason，Codex 不支持这两类。所以**复盘只能由主模型在会话里写**。主路径是显式的 `/debrief`；辅路径是在任务边界由 Stop hook 拦一次，提醒复盘。
2. 会话结束 hook 只给 1.5 秒（Claude Code 插件）/ 最多 3 秒（Codex）：只够写一个"待复盘"标记。
3. 单次注入有上限：Claude Code 1 万字符，Codex 约 2,500 token，超了只给预览。所以开会话时注入的导师规则加学习档案要压在约 1,500 token 以内。
4. Codex 的摩擦：插件 hook 要用户在 `/hooks` 里点信任；带 hook 的插件进不了 Codex 公开插件目录；IDE 扩展不支持插件。

**继承署名：**

| 方案 | 上游作者会不会出现在 contributors | 代价 |
|---|---|---|
| `git subtree add`，不 squash | 会（Duck 实测） | 仓库里多一份上游历史；上游新作者要等 `subtree pull` 才出现 |
| fork | 会 | 带 fork 标签，默认搜不到；你在 fork 里的提交不计入个人贡献图 |
| commit 里写 `Co-authored-by` | 不会（github.com 实测；官方文档里"计入共同作者"那句只出现在企业版页面） | 无 |
| README 致谢、.mailmap | 不会 | 无 |

**体积是真问题，但能绕开。** 上游当前文件树约 52MB（handbook 30.5MB、skills 13.4MB、assets 8.5MB，大头是讲义 PDF 和图片）。我在本机核了：插件市场安装用的是浅克隆（`.git/shallow` 存在），所以历史不拖累安装，拖累安装的是当前文件树。解法：分发的插件放在 `plugin/` 子目录，上游 subtree 放在插件目录之外；市场条目用 `git-subdir` 只取子目录。最后这一步需要实测。

## 四、方案草图（供讨论，不是定稿）

### 4.1 一句话

> AI 照常干活；导师把每个研究决策摊开给你看，关键的那个先听你的，干完和你复盘。会了的，它就不再管。

装它的理由不能只是"学习"。没人为了学习装插件，大家装插件是为了把活干好。所以它首先得让研究本身变好：在你被导师和审稿人问住之前，先把 baseline 太旧、seed 太少、贡献写成功能列表这些问题指出来。"你长了本事"是它和别的科研插件最不一样的地方，但不是用户装它的第一理由。

### 4.2 学习循环：四个动作

| 动作 | 做什么 | 对应你要的 | 依据 |
|---|---|---|---|
| **摊开** | agent 每做一个研究层面的决定（选数据、选 baseline、选指标、定 seed 数、解读结果、定论断范围），写一行：决定了什么、为什么、否掉了什么。记进项目里的决策记录 | 科研要点；黑盒变透明 | 认知学徒制的"示范"：把专家的思考外化 |
| **先问** | 少数关键决策，先听人的判断和一句理由，再执行。每个任务最多问一次；人说"你定"就由 AI 定，记作 AI 的决定 | 让人自己动脑的那一下 | 生成效应；Anthropic 实验里只问概念、自己动手修错的人学习没受损 |
| **复盘** | 里程碑处（实验跑完、一节写完、投稿、被拒、rebuttal 结束），由主模型写五问：本来想干什么 / 实际怎样 / 顶级导师会盯哪里（带出处）/ 这次用到的技术栈，哪些是你自己做的 / 下一步。不打分 | 学到了什么、技术栈、具体怎么做 | AAR；Maier 实验的"事后照镜子" |
| **放手** | 跨会话的个人档案记下你已经能独立做好的决策类型。这类以后不再问、不再讲 | 随你进步而变化 | 认知学徒制的"逐步撤除支架" |

"先问"和"上课"的边界用 §3.3 的四条判别式卡死：只问当前任务里的真实决策；你的回答会改变结果；只在工作事件里触发；不出分数、不出等级。

### 4.3 三个场景（请重点批注这里：哪里像上课，哪里不像你要的导师）

**场景一：跑对比实验。** 你说"帮我跑我的方法和 3 个 baseline 的对比，出个表"。

- 不装插件：agent 自己挑 baseline、自己定超参、跑一个 seed，出一张加粗的表。你不知道为什么是这 3 个，也不知道差距显不显著。组会上被问"为什么不比 X"，答不上来。
- 装了之后：
  - **先问**："跑之前写下你的预期：比最强的 baseline 高多少？"这一问本身就是研究习惯，防止跑完再编故事（H4"证据先于叙事"；Steinhardt 主张尽早试着证伪自己）。
  - **摊开**：决策记录里写着"baseline 选 A/B/C：同数据、同算力、各用论文推荐的超参；没选 D：它用了额外数据，比较不公平；seed 定 3 个"。
  - 结果出来时导师插一句："提升 0.8，seed 间标准差 1.2，审稿人会说不显著。"
  - **复盘**：你预期 +2，实际 +0.8 ± 1.2。顶级导师会盯两处：方差与显著性（NeurIPS 投稿清单第 7 项就是这个）、baseline 够不够新（`idea-evaluator` 的致命缺陷清单：baseline 超过 12 个月是红旗）。这次用到的技术：多 seed、配对 bootstrap 检验，都是 AI 做的，附一份 20 分钟能读完的材料。下一步二选一：加到 5 个 seed，或把论断改成"可比"。你选。
  - **放手**：档案记下"显著性检验：AI 做过 1 次"、"你的预期比实际高 1.2"。

**场景二：写引言。** 你说"帮我写 Introduction"。

- 不装：agent 直接交出一页漂亮的引言，贡献点是一串功能；你说不清这篇论文到底主张什么。
- 装了之后：
  - **先问**："用一句话说：读者读完应该相信什么？"如果答不上来，真正的问题就在这里，比写引言更值得先解决（H1，7 个独立来源）。
  - **摊开**：按手册 3.2 的六段结构写，每段为什么这么组织，各一行。
  - 导师卡片："贡献要写成审稿人可以攻击的主张，不要写成功能列表"（出处：`intro-drafter/references/contribution-patterns.md`）。
  - **复盘**：论证链"问题 → 缺口 → 方案 → 证据"在哪一环断了；贡献 2 在实验里还没有支撑，这是下一步。

**场景三：评估 idea。** 你说"我想做 X，帮我看看能不能做"。

- 不装：agent 给一份"很有前景"的报告。
- 装了之后：
  - **先问**："你觉得最可能让它死掉的是什么？"这一问不是考你：你知道 AI 不知道的领域约束；而且先打掉最大的风险，正是 H3 说的"以最快速度降低不确定性"。
  - **摊开**：`idea-evaluator` 逐条过致命缺陷，每条判断写清理由。
  - **复盘**：讲这次用到的评估标准本身，下次你可以自己先过一遍。

### 4.4 架构：一页本体，两层按需，一层薄适配

```
仓库/
├─ plugin/                      用户实际安装的部分，目标 < 1MB
│  ├─ ADVISOR.md                一页导师规则（≤60 行）。产品本体，常驻注入
│  ├─ cards/                    导师卡片，按需注入（每张：原则 / 为什么 / 怎么做 / 常见错误 / 出处 / 适用范围）
│  ├─ skills/                   Supervisor-Skills 的 skill（纯文本同步，一字不改）+ debrief
│  ├─ hooks/hooks.json          Claude Code 与 Codex 共用
│  ├─ hooks/advisor.(py|mjs)    单文件、零第三方依赖
│  ├─ .claude-plugin/  .codex-plugin/
│  └─ AGENTS.md                 没有插件系统的宿主用这个兜底
├─ vendor/supervisor-skills/    git subtree 导入，不 squash；只读；不随插件分发
├─ corpus/                      顶级导师来源清单与转述底稿（卡片的出处）
├─ evals/                       改导师规则之前必须过的对照评测
└─ LICENSE（代码 MIT） + LICENSES/（内容 CC BY-NC-SA 4.0，按目录写清）
```

五个 hook，全部是确定性脚本，不在 hook 里调 LLM：

| 事件 | 干什么 | 预算 |
|---|---|---|
| SessionStart | 注入 ADVISOR.md 和档案摘要（最近的决策习惯、没收尾的复盘） | ≤ 1,500 token |
| UserPromptSubmit | 按关键词判断你在哪个科研阶段，注入最多 2 张相关卡片的摘要 | 命中才注入，≤ 600 token |
| PostToolUse | 记一行事件，识别里程碑（实验脚本跑完、PDF 编译完、某节写完） | 通常不注入 |
| Stop | 有里程碑、还没复盘时拦一次，请主模型写复盘；查 `stop_hook_active` 防循环 | 一次 |
| SessionEnd | 只写"待复盘"标记，下次开会话时提醒 | < 1.5 秒 |

- **命令只有两个**：`/debrief`（复盘）和 `/advisor on|quiet|off`（档位）。
- **数据全在本地**：项目里 `.advisor/decisions.md`（决策记录，顺便可以当 AI 使用披露的底稿）和 `.advisor/debriefs/`；个人档案 `~/.advisor/profile.md`。不上传，不要账号，不做遥测。
- **三条硬规则写进 ADVISOR.md**：
  1. 导师的话只出现在对话和 `.advisor/` 里，绝不写进你的论文和代码（Ponytail #120、#737 的教训）；
  2. 不往审稿类子 agent 里注入（#502）；
  3. 只在有研究动作的轮次说话。
- **运行时依赖**：只需要一种解释器，Python 3 标准库或 Node 二选一（见 D6）。缺了也不报错：hook 静默失效，skill 照常可用。

### 4.5 MVP：做什么、不做什么、怎么验收

**做**：
- 一页导师规则、四个动作、两个命令，Claude Code 和 Codex 同时支持。
- 约 40 张卡片：先补手册的空白（实验统计、局限性、选题与读论文、组会报告），再从手册和 skill 里拆（盘点里已有 15 张样例）。
- subtree 导入最新上游，包括 9 月的 `rebuttal-guidance`。

**不做**：
- 门禁、证据文件、LaTeX 工具链（Duck 那一套）。
- 分数、等级、测验、学习计划。
- 云端、账号、遥测。
- Cursor、Gemini 等宿主（MVP 只给 AGENTS.md 兜底）。

**验收**（防止再做出一个 Duck）：
1. 在你自己的 3 个真实任务上跑：一次实验、一节写作、一次 idea 评估。README 首屏放真实收据：前后对比加复盘截图。
2. 一个能复现的小评测，借 Shen & Tamkin 的设计：同一任务，装和不装，事后问 5 个"这次为什么这么做"，看答不答得上来。只当演示，不当论文结论。
3. 每轮注入多少 token 写进 README，成本如实交代。
4. 改导师规则之前，先在 `evals/` 跑对照。

**节奏**：先用几天搭出能跑通一个场景的最小骨架，在真实任务里看效果再定细节。不写 19 项任务的大计划。

### 4.6 最大的风险

| 风险 | 怎么防 |
|---|---|
| 没人为"学习"装插件 | 第一卖点放研究质量（在导师和审稿人之前挑出问题）；学习是差异点 |
| 问多了被卸载 | 每个任务最多问一次；"你定"永远可以；`quiet` 档 |
| 导师口吻污染论文文风 | 硬规则：导师的话不进用户文件 |

### 怎么讨论

Duck 的历史里，你两次扭转方向（"变成上课了"、"我们是和作者一起写论文"），都是看到具体场景时才发生的，读抽象 spec 时没有。所以我建议这样讨论：

1. **这一轮，你批注，大约半小时**：在 §4.3 三个场景上批注哪里像上课、哪里不像你要的导师；§5 的决策逐条回"同意"或"改成 X"。
2. **下一轮，我出东西**：2 页 spec 加仓库骨架（subtree 导入、`plugin/` 目录、一页导师规则、5 个 hook），再把其中一个场景端到端跑通。
3. **再下一轮，一起看收据**：在你一个真实任务上跑一次，对着真实输出改规则。
