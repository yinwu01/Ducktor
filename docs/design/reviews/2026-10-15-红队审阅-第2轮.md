## 二、重要

### 重要 1：两个命令放在 `commands/`，在 Codex 上不存在，在 Claude Code 上是旧格式

原文（§4.4 目录树）：
> │  ├─ commands/                 /debrief、/advisor

原文（§4.4）：
> **命令两个**：`/debrief`（复盘）和 `/advisor on|quiet|off`（开关和档位）。

问题：附件 D §1 写明 Claude Code "技能即 /name，commands/ 为旧格式"；Codex 的插件组件是 "skills、MCP、apps、浏览器扩展、hooks，未见 agents、commands"，自定义 prompt 已废弃。v0 的目录树把 debrief 放在 `skills/` 下（"+ debrief"），v1 去掉上游 skill 拷贝时把它一并挪进了 `commands/`，这是回退。MVP 的"两个命令"在第二个宿主上装不上，而"Claude Code 和 Codex 同时支持"是用户的原始要求。

改法：
- `/debrief` 做成 `skills/debrief/SKILL.md`，两边都是斜杠或 `$debrief` 可调（附件 D §6 原本就是这么推荐的）。
- `/advisor on|quiet|off` 不做成命令，由 UserPromptSubmit hook 解析用户输入里的这一句，Ponytail 就是这么处理 `/ponytail lite|full|ultra|off` 的（附件 A §2）。顺带 `.advisor/` 目录可以由 hook 脚本直接创建，不经过模型。
- §4.2 复盘、§4.3 场景四里提到 `/debrief` 的地方加一次"（Codex 里是 `$debrief`）"。

### 重要 2："不放 skill 拷贝"让 A 方案变成两次安装，这个代价没写；给的理由没有依据

原文（§4.4）：
> **上游 skill 不在插件里放拷贝。** ADVISOR.md 按名字调用它们（写引言时用 `intro-drafter`），用户自己装 Supervisor-Skills。原因：很多目标用户已经装了，两份同名 skill 会撞车；插件里每个 skill 的描述在每个会话都占上下文。发布前再决定要不要内置。

原文（§3.1 共性）：
> 两步以内装完

原文（§1.1）：
> | 3. 结合现有全部 skill | 不重写 skill。卡片从手册和 skill 里提炼并注明出处；干活时直接调用上游 skill；导师层套在外面，负责摊开、提问、复盘 |

问题：
1. 在 D1 选 A 时，用户要先装插件（两条命令），再另外装 Supervisor-Skills（上游是一句话 prompt 让 agent 自装）。三步，和 §3.1 自己总结的"两步以内装完"冲突，也和用户第一条要求"容易适配"冲突。场景一的"导师卡片"要调 `idea-evaluator`，没装上游的用户跑不通。这个代价在 §4.4 和 D1 表里都没有出现。
2. "很多目标用户已经装了"是我第一轮写的，v1 照搬了。本机核了四个 skill 目录（`~/.claude/skills`、`/SSD1/wuyin/.claude/skills`、`~/.agents/skills`、`~/.codex/skills`），11 个上游 skill 一个都没装，连用户自己都没装。这句话没有依据，站得住的理由只有后一条（上下文成本）和"不维护第二份拷贝"。
3. 这件事反过来是 B 方案的一个硬优势：B 里插件和 skill 在同一个仓库，一次装完。D1 表应当有这一行。

改法：
- §4.4 该段改成："不放拷贝的代价是 A 方案要装两样东西；MVP 先接受，插件启动时检测上游 skill 装没装，没装就提示一句安装命令。"删掉"很多目标用户已经装了"。
- D1 表加一行"安装步骤：A 两步装插件 + 另装 Supervisor-Skills；B 一次装完"。
- 发布前的选项再加一条：把 Supervisor-Skills 本身做成插件并声明为依赖（附件 D §2：plugin.json 支持 dependencies），这样 A 也能一次装完，但需要上游配合。

### 重要 3："只提一次"和"每次会话注入未复盘条数"互相矛盾

原文（§4.4 hook 表）：
> | SessionStart | 注入 ADVISOR.md、"别再问"清单、还没复盘的决策条数 | ≤ 1,500 token | 做 |

原文（§4.3 场景四）：
> 跑完你直接关掉窗口：不拦你。下次在这个项目里开会话，它提一句"上次有 4 个研究决策还没复盘，想做就 `/debrief`"；你不理，它不再提。

问题：表里的 hook 每次开会话都注入条数，模型每次都会看到"有 4 条没复盘"，场景四却承诺"你不理，它不再提"。两者只能成立一个。要做到只提一次，hook 得记一个"这批已提醒过"的标记，并定义"不理"的判据（下一次会话没敲 `/debrief` 就算不理）。这正是协调者说改成了的东西，但表里没落下来。

改法：hook 表该行改成"注入 ADVISOR.md、'别再问'清单；有未复盘决策且这批还没提醒过时，附一句提醒，提醒后记标记，不再附"。场景四保持不变。

## 三、次要

### 次要 1：一句没有依据的判断
原文（§4.3 场景二）：
> 放进来是因为写作占研究生的时间最多。
问题：没有出处。用户对无据的概括很敏感，而这句完全可以不要。
改法："放进来是因为它最常见"。

### 次要 2：§1.2 没跟上 §3.4 的新解法
原文（§1.2 第 2 条）：
> 还要把上游约 52MB 的文件（大头是一个 16.6MB 的讲义 PDF 和一批图片）放进仓库。
问题：§3.4 (b) 已经说可以在 subtree 之后删掉大文件，留在历史里的不拖累安装。这句仍按 v0 的理解写。
改法："还要把上游历史（含 52MB 的文件）导进仓库，当前树可以瘦身，见 §3.4"。

### 次要 3：D1 表的"即可"比 §3.4 的"推断"更有把握
原文（§5 D1 表）：
> 在 vendor 里删大文件即可瘦身（§3.4 的 b）
原文（§3.4）：
> contributors 应当不受影响（推断）
改法："删大文件可望瘦身（待实测，§3.4 的 b）"。

### 次要 4："已核"的含义
原文（§〇 第 4 条）：
> Claude Code 和 Codex 可以共用一份 hook 配置（已核）。
问题：核的是文档和 Ponytail 的做法，我们自己的配置还没在两边跑过。
改法："（文档支持，Ponytail 已这么做）"。

### 次要 5："才有效果"略超证据
原文（§〇 第 3 条）：
> 复盘要本人参与才有效果。
问题：Tannenbaum 的元分析只研究了参与式复盘，没有对照"发报告"；Maier 的被动镜子反而有效。§3.3 的措辞"复盘要本人参与才算数"是设计口径，没问题；§〇 这句是证据口径，过了一点。
改法："有效果的复盘都是本人参与的"。

### 次要 6："任务"没有定义
原文（§4.2 先问）：
> 每个任务最多问一次；你说"你定"，就由 AI 定，记作 AI 的决定
问题：场景四写"这个任务里不再问"，但"任务"是一条请求、一个会话还是一个里程碑，没说。实现时这决定计数器在哪清零。
改法：加半句"一次请求到交付算一个任务"。

### 次要 7：复盘里现在有两处要你开口
原文（§4.2 复盘）：
> 导师再补五问：本来想干什么 / 实际怎样 / 顶级导师会盯哪里（带出处）/ 这次哪些判断交给了 AI，下次这一类想不想自己来 / 下一步。
问题："想不想自己来"是一个问句，加上开头的"先请你说一句"，一次复盘要人答两次。它是用户自己敲 `/debrief` 换来的，可以接受，但这是"上课味"最容易回潮的位置。
改法：第四问改成陈述加可选："这次 seed 数是 AI 定的；下次想自己定就回一句。"

### 次要 8：硬规则 2 里的"档案"已经没有所指
原文（§4.2 硬规则）：
> 2. 档案和清单里不出现任何对你的评价，不做成长档案；
改法："决策记录、复盘和清单里不出现任何对你的评价"。

### 次要 9：关键词识别阶段的误报成本没列进风险
原文（§4.4 hook 表）：
> | UserPromptSubmit | 按关键词判断你在哪个科研阶段，注入最多 2 张相关卡片的摘要 | 命中才注入，≤ 600 token | 做 |
问题：确定性脚本按中英文关键词判阶段，误命中一次就多塞 600 token 的卡片，而且用户看不见。这是 MVP 两个 hook 之一，§4.6 没有这一行。
改法：MVP 的关键词表只覆盖场景一（baseline、seed、对比、显著）；hook 把命中和未命中记进本地日志，发布前用真实会话调表。§4.6 加一行。

### 次要 10：D12 和重叠检查对不上
原文（§5 D12）：
> 规则和卡片用英文写（给模型读，也和上游 SKILL.md 只用英文的 lint 一致）
原文（§3.6）：
> 发布前加一道检查，转述与原文连续 12 个词以上相同就报警。
问题：手册出处是中文，卡片是英文，连续 12 个词的重叠检查跨语言失效；上游的英文 lint 只在 D1 选 B 时约束我们。两点都值得各加半句，免得用户以为检查覆盖了手册来源。
改法：D12 理由里加"上游 lint 只在 B 方案下约束"；§3.6 加"中文来源的卡片靠人工核转述"。

### 次要 11：丢掉"写预期"丢得有点彻底
原文（§4.2 先问）：
> 也不问"你猜结果是多少"这种答了也不改变任何事的问题
问题：不问是对的。但"跑之前写一行预期"本身是 H4（Steinhardt、Nanda）支持的研究习惯，可以作为决策记录里的可选一行，由人想写就写，永远不问。v1 把它整个删了。
改法：§4.2 摊开那一格加半句"你想写预期可以自己写一行，它不问"。

## 五、用户第一遍读最可能否掉的地方

按可能性排：

1. **§4.4 "上游 skill 不在插件里放拷贝"。** 用户的原话是"结合我们目前所有的 skill 里面的内容"，读到"用户自己装 Supervisor-Skills"会觉得插件没把自家 skill 装进去，再读到要装两样东西，更会问"这还叫轻量？"。重要 2 的改法能化解，但也可能把他推向 D1 的 B。那不是坏事，文档要让他看见这是同一个决定的两面。
2. **D12 "规则和卡片用英文写"。** 他说的目标用户是"普通研究生"，中文语境；看到卡片是英文，第一反应可能是"给谁用的"。理由里要把"导师跟你说话跟着你用的语言"提到最前面，并写明用户面向的文本全部中文可用。
3. **§4.2 复盘的两次开口**（次要 7）。他 7 月否决过"课前提问"，复盘里连问两句是他最可能嗅到上课味的地方，哪怕是他自己敲的 `/debrief`。
4. **§4.3 场景四 "它问'seed 跑几个'"。** deadline 前一天还被问一句，他可能直接说"这种时候一个字都别问"。场景四已经给了 `quiet` 档，但可以加一句：开 quiet 之后连"先问"也不问，只记录。原文已经写了"也不问"，位置在第二条；建议把 quiet 那条挪到第一条，让他先看到出口。
