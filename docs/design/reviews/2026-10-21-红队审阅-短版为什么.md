# 红队审阅：命令收尾的短版「为什么」改成导师口吻

2026-10-21，审 why-mentor 分支 bd612f4 到 3f6066c。审的人只读不改，看的是这一轮的改动和真模型跑出来的原文（CC main 06-16-40、CC more 06-32-20、Codex main 和 more 06-32-27，对照 10-20 改之前的几轮）。修改在 b90b55b，重跑结果见 docs/testing.md「上一次的结果」。

结论：没有致命问题，下面几条要修。

1. Codex 把「原技能要求」换成了「这对应 E02」。9 条短版全挂 E02，没有一条点名家，more 里 6 条是同一个句式。卡号成了新的拐杖，学生看不出那张卡讲了什么。CC main 的 idea、review 两条也是卡号标签加一句对账。根子是模板写「依据从卡片……里找」，读起来像必须挂一个出处。
   修改：理由去掉出处也要讲得通；出处可以没有，至多一处，要点就说清是谁、讲了什么，不只挂卡号；对不上不硬凑。
2. 回复里的人名和书名逐条对过 MENTORS.md 和卡片，没有编造。问题在笔记本：把延伸用法记成了名家出处，鸭子已经收回的「T01」也留在笔记本里。另外「你 MM-DD 记下的」把 AI 写的条目算到学生头上，和 /duck-why「AI 做的不要说成学生做的」冲突。
   修改：命令和常驻规则的笔记本出处照 /duck-why 的写法；旧条目写成「笔记本 MM-DD 那条」，不算出处。
3. 模板、常驻规则和测试对「笔记本算不算依据」说法不一。
   修改：三处统一为可以接着用，不算出处。
4. 三项检查空过：找不到引用块时直接算过；引用块中间有空行会被切开；理由检查会误伤「原技能写 X，我降成 MAJOR，因为……」这种如实交代；人名检查只看带「说、认为」的句子，「讲的是」「批评过」都漏；标签漏了「取舍：」「下次自己先做：」。
   修改：都改了，另加两条全局 should：同一卡号出现在一半以上的短版里；回复里出现「你 MM-DD 记下的」。
5. 追问一次后保留注入内容的修复没被跑到过；Codex 下追问后也该重读会话记录。
   修改：追问后 Codex 重读一次。

   修改：报告那段和笔记本出处按同一条规矩改。
7. 措辞：「不写泛泛的道理」紧挨着「背后的道理」读起来矛盾，改成「不写换个项目也成立的空话」；第一项改成至多两句。
