# 导师插件：怎么运行、为什么这样设计、用起来什么样

这份是讨论稿 v1 第四章的白话版，按你刚定的 D2 到 D4 写：先放你名下；不商用，卡片直接改编手册；四个动作都做。仓库怎么建（D1）不影响插件怎么运行，另外说。

## 一句话

AI 照常干活；导师把每个研究决策摊开给你看，要你拍板的先问你，干完和你一起复盘；你说会了的，它就不再管。

它不是另一个 agent，也不是常驻后台的程序。它是一页导师规则加一组卡片。Claude Code 和 Codex 都有 hook，就是宿主在固定时刻（开会话、你每发一句话）自动运行的脚本。我们用 hook 在对的时候把规则和卡片放进上下文，由正在给你干活的那个模型边干边照着做。

## 一、装上之后多了什么

| 东西 | 是什么 | 谁来执行 |
|---|---|---|
| 导师规则 `skills/advisor/SKILL.md` | 一页，不超过 60 行：四个动作怎么做、什么时候不说话、几条硬规则 | 主模型读了照做 |
| 卡片 `cards/` | 一张卡一条标准：原则、为什么、怎么做、常见错误、出处、适用范围。MVP 只有 6 到 8 张，管跑对比实验：baseline 怎么选、对比公不公平、seed 和方差、显著性检验、论断说到多大 | hook 按需放进上下文 |
| 复盘 `skills/debrief/SKILL.md` | 复盘的步骤和格式 | 你敲 `/debrief` 时主模型照做 |
| hook 脚本 `hooks/advisor.py` | 一个 Python 文件，只用标准库，不调用任何模型 | 宿主自动运行 |
| 项目里的 `.advisor/` | 开关标记、决策记录 `decisions.md`、复盘存档 `debriefs/` | 普通文件，留在本地 |
| `~/.advisor/skip.md` | "这类我会了"清单，跨项目生效 | 普通文件 |

主模型指 Claude Code 或 Codex 里正在跟你对话、给你干活的那个模型。

用户装的只是 `plugin/` 这个子目录，目标不到 1MB。仓库里的老版本 Supervisor-Skills（约 51MB，大头是讲义 PDF 和图片）是写卡片的原料；怎么不让它跟着装，发布前实测，讨论稿 §3.4 有两条候选办法。

## 二、运行原理

### 2.1 一次会话里发生什么

```
① 开会话（SessionStart hook）
   advisor.py 看当前项目里有没有 .advisor/
   ├─ 没有：直接退出，什么都不加。没开过导师的项目里，导师不存在
   └─ 有：把导师规则和你的"别再问"清单放进上下文（≤1,500 token）
          有还没复盘的决策时附一句提醒；同一批只提醒一次

② 你每发一句话（UserPromptSubmit hook）
   ├─ 是 /advisor on | quiet | off：脚本直接切开关（on 时建 .advisor/），不经过模型
   └─ 话里命中某个科研阶段的关键词（MVP 只认跑实验这一类）：
      附上最多 2 张相关卡片的摘要（≤600 token）；没命中就什么都不加

③ 主模型照常干活：读代码、改代码、跑实验、写东西。同时照规则做：
   ├─ 碰到要你拍板的决策：先问你，再动手（每个任务最多问一次）
   ├─ 这一轮做了研究决策：回复末尾摊开一行，同一行追加进 .advisor/decisions.md
   └─ 你说"这类别问了"：记进 ~/.advisor/skip.md

④ 到了里程碑（实验跑完、一节写完、投稿、被拒、rebuttal 结束）
   你敲 /debrief：你先说一句（可以跳过），主模型补五项，存进 .advisor/debriefs/
```

"任务"指你的一次请求到交付。"研究决策"指选数据、选 baseline、选指标、定 seed 数、解读结果、定论断范围这一类；没有研究决策的轮次，回复里一个字不加。你想在决策记录里写一行自己的预期，可以自己写，它不问。

### 2.2 为什么这样设计

1. 本体是一页提示词，生效靠自动注入。Ponytail（164k 星）的核心只有一个 52 行的 SKILL.md，其余约 2,400 行全是 hook 和适配器，用来把这一页送进各个宿主。JetBrains 测过（原文打不开，两篇转述一致）：只装 skill、不装 hook，10 次会话一次都没自动触发。所以导师规则不能等模型自己想起来加载，要由 hook 在开会话时放进去。

2. hook 只送内容、记状态，导师的话由正在干活的模型说。这是宿主的限制逼出来的：hook 不能让模型写正文。Claude Code 的 prompt 型、agent 型 hook 只能回"通过/不通过"加一句理由，Codex 不支持这两类。好处是导师和干活的 AI 共用同一个上下文，它确切知道刚才做了什么决定，不需要第二个模型，也不多花一次调用。代价是守不守规矩全看主模型。对策有四条：每次开会话重新注入；卡片命中时附一行规则提醒；改规则前跑对照评测；用真实会话抽查。

3. 人只在两处动脑，而且都是做研究本来就要做的事。调研里的证据指向同一处：伤学习的主要是把思考外包出去，不是用 AI 本身；只读一份 AI 写的总结，人会觉得懂了，其实没长本事；复盘要本人参与才有效。所以设计成：要拍板的决策你先表态（先问），复盘时你先说一句。先问只问你的回答会改变计划的事，不问考你知识的问题，也不让你猜结果，因为你 7 月否决过课前提问。每个动作都要过四条判别式，破一条就不做：对象是当前任务里的真实决策或产物；你的回答会改变结果；由工作里的事件触发，不按课程表；不显示分数或等级。

4. 放手由你说了算。不出题，就没法可靠地判断你会不会，所以"会了"只由你说。清单里只有你说过的话，模型不自己推断，也不写任何对你的评价。

5. 不拦人。不在收工时拦你，也就是不拿 Stop hook 做门禁。Duck 的教训是：门禁和被管的 agent 在同一台机器上，证据能伪造，最后工程量全花在防 agent 偷懒上。导师只说话；你随时可以说"你定"、"这类别问了"，或者切到 quiet。

### 2.3 知识从哪来，怎么进上下文

- 卡片的来源：Supervisor-Skills 的手册和 skill（D3 定了不商用，可以直接改编，内容跟着 CC BY-NC-SA），加顶级导师经验里核实过的 8 条共识，比如"动手前先写出 1 到 3 条可检验的核心主张"、"证据先于叙事"。每张写明出处和适用范围。手册没讲实验统计（seed、方差、显著性），候选来源是 NeurIPS 投稿清单第 7 项和两篇方法论文，许可还要再过一遍。
- 按需放，不一次全塞：开会话只放规则，之后每次最多 2 张卡片的摘要。宿主对单次注入有上限（Claude Code 1 万字符，Codex 约 2,500 token），而且上下文要留给干活。
- 和现有 skill 的关系：装了 Supervisor-Skills 的，规则会让主模型在合适的时候调用对应 skill（写引言用 `intro-drafter`，评估 idea 用 `idea-evaluator`）；导师套在外面负责问、摊开、复盘，不重写这些 skill。没装的，`/advisor on` 时提示一句，规则和卡片照常工作。

## 三、运行场景

MVP 阶段，四个动作在任何科研任务里都生效，因为规则是通用的；专门的卡片先只有跑实验这一类。写作、选题、组会报告的卡片发布前补齐，约 40 张。下面的对话都是示意。

### 场景一：跑对比实验（MVP 要跑通的就是这个）

1. 第一次用：你在项目里敲 `/advisor on`。hook 建 `.advisor/`，回一句"导师已在这个项目开启"。
2. 你："帮我跑我的方法和 3 个 baseline 的对比，出个表。"hook 命中"对比"、"baseline"，附两张卡片：baseline 怎么选（同数据、同算力、够新），seed 和方差。
3. 准备时，模型发现候选里的 D 用了额外数据，先问："D 用了额外数据。比不比？比的话表里要注明。"这一问决定表里有几列、审稿人会不会追问，只有你能拍板。这个任务里只问这一次。
4. 你："比，加脚注。"seed 数你没提，模型定 3 个，记作 AI 的决定。
5. 交付时，回复末尾一行："baseline 选 A/B/C：同数据、同算力、各用论文推荐的超参；D 按你的意思放进表、加脚注；seed 定 3 个（AI 定的）。"同一行写进 `decisions.md`。
6. 结果出来，模型插一句："提升 0.8，seed 间标准差 1.2，按这个方差，审稿人会说不显著。"
7. 你敲 `/debrief`。它先请你说一句；你说："D 是我定的；seed 太少，最想重来。"导师再补五项：
   - 本来想干什么：证明比最强的 baseline 好；
   - 实际怎样：+0.8 ± 1.2，不显著；
   - 顶级导师会盯哪里：方差与显著性（NeurIPS 投稿清单第 7 项），baseline 够不够新（`idea-evaluator` 把超过 12 个月的 baseline 列为红旗）；
   - 这次交给 AI 的判断：seed 数、显著性检验的做法；下次想自己定，回一句就行；
   - 下一步：加到 5 个 seed，或者把论断改成"可比"，你选。

   你说的那句和决策记录并排放在复盘里，不打分。
8. 你回："显著性检验这块我会了，别讲了。"它记进 `skip.md`，以后这一类只做不讲。

`decisions.md` 里大概是这样（示意）：

```
- 10-16 实验｜baseline 选 A/B/C：同数据、同算力、论文推荐超参｜AI 定
- 10-16 实验｜D 放进表并加脚注：用了额外数据｜你定
- 10-16 实验｜seed 定 3 个｜AI 定
```

### 场景二：写引言

- 先问："用一句话说：读者读完应该相信什么？"答不上来的话，真正的问题就在这里，比写引言更值得先解决。
- 摊开：按手册 3.2 节的六段结构写，每段为什么这么组织，各一行。
- 卡片："贡献要具体到可以被证伪。"
- 复盘：你先说最没把握的是哪段；导师补论证链（问题、缺口、方案、证据）在哪一环断了。

### 场景三：评估 idea

- 先问："你觉得最可能让它死掉的是什么？"这不是考你：你知道 AI 不知道的领域约束，你的回答决定先查哪一条。
- 摊开：`idea-evaluator` 逐条过致命缺陷，每条写清理由。
- 复盘：你先说现在还想不想做；导师补这次用到了哪几条标准、各自的出处。

### 场景四：不顺的时候

- 赶 deadline 不想被打扰：敲 `/advisor quiet`。只往决策记录里写，不在对话里说话，一个问题也不问。
- 它问 seed 跑几个，你回"你定"：记成 AI 的决定，这个任务里不再问。
- 问了个你觉得多余的问题：回"这类别问了"，以后同类不再问。
- 跑完直接关窗口：不拦你。下次在这个项目里开会话，它提一句"上次有 4 个研究决策还没复盘，想做就 /debrief"；你不理，它不再提。
- 在别的项目里（改服务器脚本、写邮件）：一个字都不说，因为你没在那里开过导师。

## 四、它不做什么

- 不拦你收工，不做门禁，不要证据文件。
- 不打分，不出题，不布置作业，不建成长档案。
- 导师的话只出现在对话和 `.advisor/` 里，不写进你的论文和代码。Ponytail 用户骂得最凶的，就是往用户代码里写品牌注释、人设口吻传染到用户自己的文档。
- 不往审稿类子 agent 里注入。Ponytail 一律注入以后，审稿子 agent 少报了问题。
- 不上传，不要账号，不做遥测。

## 五、还要在真实任务里验证的

1. 模型守不守规矩。长会话里规则可能被淡忘，口吻可能走样；对策见 2.2 第 2 条，最后要看真实会话。
2. 什么算研究决策、什么算里程碑。MVP 靠关键词加主模型判断。自动识别"实验跑完"先不做，因为脚本分不清冒烟测试和正式实验。
3. 问的分寸。"每个任务最多问一次"是先定的上限，要在你的真实任务里调。
4. Codex 那边的摩擦。插件 hook 要在 `/hooks` 里点一次信任；带 hook 的插件进不了 Codex 的公开插件目录。MVP 先在 Claude Code 上跑通，同一份配置接着上 Codex。
